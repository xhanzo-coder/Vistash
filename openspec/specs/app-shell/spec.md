## Requirements
### Requirement: 库位置由使用者显式选择并被记住

首次运行时，应用 MUST（必须）要求使用者显式选择库位置，MUST NOT（禁止）在默认路径静默创建库。原因是库会承载素材本体的完整副本，规模可增长到数十 GB，落在系统盘的默认目录会产生使用者未同意的后果。

再次启动时，应用 MUST（必须）直接打开上次使用的库，MUST NOT（禁止）重复询问。若记录的库路径不存在或不可读，应用 MUST（必须）显式告知并回到选择界面，MUST NOT（禁止）静默创建一个新库——那会使使用者面对一个空库却以为素材丢失。

若使用者选择的目录已经是一个 Vistash 库，应用 MUST（必须）按打开处理而非重新创建。若该目录非空且不是 Vistash 库，应用 MUST（必须）拒绝并说明原因，MUST NOT（禁止）在其中混入库骨架。

#### Scenario: 首次运行

- **WHEN** 使用者第一次启动应用
- **THEN** 应用要求选择库位置，且在使用者做出选择前不创建任何库文件

#### Scenario: 再次启动

- **WHEN** 使用者在已选定库之后再次启动应用
- **THEN** 应用直接打开该库，不再询问库位置

#### Scenario: 上次的库路径已不可用

- **WHEN** 记录的库路径已被移动或删除
- **THEN** 应用显式告知该路径不可用并回到选择界面，不创建新库

#### Scenario: 选择一个已经是库的目录

- **WHEN** 使用者选择的目录中已存在 `library.json`
- **THEN** 应用打开该库，不覆盖其中任何既有文件

#### Scenario: 选择一个非空且非库的目录

- **WHEN** 使用者选择的目录含有其他文件但没有 `library.json`
- **THEN** 应用拒绝在该目录建库并说明原因

### Requirement: 库骨架的创建与格式版本校验

创建库 MUST（必须）写入携带格式版本、内容哈希算法标识与创建时间的库级元数据文件，并 MUST（必须）建立文件夹树文件、素材本体目录、回收站目录与提示词记录目录。

打开库 MUST（必须）先校验库级元数据文件存在且其格式版本可被当前程序识别。格式版本高于当前程序支持的版本时，应用 MUST（必须）拒绝打开并显式告知，MUST NOT（禁止）尝试按当前格式读取。原因是按旧代码读取更高版本的格式会产生静默的错误解释，进而在写回时损坏数据。

库级元数据文件缺失或无法解析时，应用 MUST（必须）报告库损坏并拒绝打开，MUST NOT（禁止）通过重建该文件的方式自行恢复——哈希算法标识无法从素材本体反推，猜错会使全库去重判定失效。

#### Scenario: 创建一个新库

- **WHEN** 使用者在空目录中创建库
- **THEN** 库级元数据文件、文件夹树文件、素材本体目录、回收站目录与提示词记录目录全部就位

#### Scenario: 打开格式版本更高的库

- **WHEN** 库级元数据文件记录的格式版本高于当前程序支持的版本
- **THEN** 应用拒绝打开并显式告知版本不受支持，不读取其中任何素材

#### Scenario: 库级元数据文件缺失

- **WHEN** 目录中存在素材本体目录但库级元数据文件缺失
- **THEN** 应用报告库损坏并拒绝打开，不自行重建该文件

### Requirement: 导航结构与未实现入口的呈现

导航 MUST（必须）在紧凑顶栏中提供图片素材与提示词两个一级入口，且提示词库 MUST（必须）是一级入口，MUST NOT（禁止）实现为图片详情的从属侧栏。两个入口 MUST（必须）切换同一工作台外壳内的分类、中央视图与检查器内容，MUST NOT（禁止）让品牌头部占据大片垂直空间。

本次尚未实现的入口 MUST（必须）显式呈现为未实现，MUST NOT（禁止）呈现为空列表。图片反推、生图和 provider 配置 MUST NOT（禁止）作为本变更的可操作入口出现。

#### Scenario: 切换两个素材库

- **WHEN** 使用者在紧凑顶栏中从图片素材切换到提示词
- **THEN** 左侧分类、中央视图和右侧检查器切换为提示词库上下文，顶栏与库路径保持稳定

#### Scenario: 未实现能力不冒充可用

- **WHEN** 当前版本尚未实现图片反推或生图
- **THEN** 应用不显示可执行的反推或生图主操作，也不用空结果页暗示能力已实现

### Requirement: 失败信息必须带错误码呈现

任何携带错误码的失败 MUST（必须）向使用者同时呈现错误码本身与可读说明，MUST NOT（禁止）只显示通用失败文案。原因是错误码是本项目诊断问题的唯一稳定标识，只显示通用文案会使失败无法归因。

批量操作中的失败 MUST（必须）可逐条查看，MUST NOT（禁止）只报告失败总数。

#### Scenario: 单个素材导入失败

- **WHEN** 某个素材因磁盘写入失败而未能导入
- **THEN** 界面同时显示对应错误码与可读原因

#### Scenario: 批量导入中部分素材失败

- **WHEN** 一批导入中若干素材失败、其余成功
- **THEN** 使用者可逐条查看每个失败素材的文件名与错误码，而不是只看到失败数量

### Requirement: 界面层不读取像素

界面层 MUST（必须）只通过后端命令获取已生成的缩略图与色卡结果。界面层 MUST NOT（禁止）使用 `Canvas`、`OffscreenCanvas` 或 `ImageData` 读取像素值执行缩放、采样或聚类。

呈现原图 MAY（可以）通过标准图像元素完成，因为那是渲染而非像素读取，不构成对本约束的削弱。

#### Scenario: 渲染缩略图网格

- **WHEN** 网格显示素材缩略图
- **THEN** 界面层使用后端已生成的缩略图数据，不在前端执行任何缩放或采样

#### Scenario: 渲染单图预览

- **WHEN** 预览显示素材原图
- **THEN** 原图通过标准图像元素渲染，界面层不读取其像素值

### Requirement: 批量导入期间界面保持响应并呈现进度

批量导入的目录扫描、哈希、文件复制、图像解码、缩略图生成、色卡计算与索引写入 MUST（必须）在窗口事件线程之外执行。导入进行期间窗口 MUST（必须）继续响应重绘、移动、最小化与导航输入，MUST NOT（禁止）因批量处理而被 Windows 标记为未响应。

完成源文件展开后，界面 MUST（必须）呈现已处理数量、总数量与当前文件名，并 MUST（必须）随每个素材开始处理而更新。一次导入尚未结束时，后续拖入 MUST NOT（禁止）启动与其重叠的库写入；界面 MUST（必须）保留当前任务的进度状态。

#### Scenario: 导入一百张素材

- **WHEN** 使用者拖入一个包含一百张受支持图片的目录
- **THEN** 导入在后台执行，窗口持续响应，界面进度从零推进到一百

#### Scenario: 导入进行时再次拖入

- **WHEN** 前一批素材仍在导入且使用者再次拖入文件
- **THEN** 应用不启动重叠的第二个导入任务，当前任务继续执行且进度不被重置

### Requirement: 可调整三栏工作台与独立布局记忆

每个素材库 MUST（必须）使用“左侧分类—中央集合—右侧检查器”的稳定桌面工作台。左右两栏 MUST（必须）支持调整宽度与折叠，中央内容 MUST（必须）获得剩余空间。图片库与提示词库 MUST（必须）分别保存左/右栏宽度、折叠状态、中央视图、当前文件夹、筛选与滚动位置。

单击一个项目 MUST（必须）只更新活动项与右侧检查器，MUST NOT（禁止）用整页详情替换中央集合。双击或 `Enter` MUST（必须）进入聚焦模式，`Esc` MUST（必须）返回原集合位置。

#### Scenario: 图片与提示词记住不同布局

- **WHEN** 使用者在图片库展开右检查器、在提示词库折叠右检查器后来回切换
- **THEN** 两个素材库各自恢复先前的栏位与中央视图状态

#### Scenario: 单击不丢失集合上下文

- **WHEN** 使用者在瀑布流中单击一个项目
- **THEN** 右侧检查器展示该项目，中央瀑布流保持原滚动位置与可见项

### Requirement: 全局搜索与当前库局部搜索

顶栏 MUST（必须）提供跨图片和提示词的全局搜索，结果 MUST（必须）按素材类型分组并显示各组数量，MUST NOT（禁止）混入一个无类型瀑布流。当前库 MUST（必须）同时提供只作用于当前图片查询或提示词查询的局部搜索，并把已应用条件呈现为可移除的明确状态。

`Ctrl+K` MUST（必须）聚焦全局搜索，`Ctrl+F` MUST（必须）聚焦当前库搜索。从全局结果进入某项后 MUST（必须）切换到对应素材库并定位该项。

#### Scenario: 全局搜索同时命中两类素材

- **WHEN** 使用者在全局搜索中输入同时匹配图片标签与提示词正文的文本
- **THEN** 结果分别列出“图片素材”与“提示词”组，两组可独立跳转

#### Scenario: 局部搜索不泄漏到另一库

- **WHEN** 使用者在提示词库按 `Ctrl+F` 搜索正文
- **THEN** 查询只约束提示词中央列表，不改变图片库查询状态

### Requirement: 窄窗口适配与语义主题

工作台 MUST（必须）在窗口变窄时优先保留中央内容：中等宽度下左栏 MUST（必须）可折叠为按需展开的导航，更窄时右检查器 MUST（必须）作为覆盖式抽屉，MUST NOT（禁止）依赖固定最小宽度造成水平滚动。

界面样式 MUST（必须）使用表达表面、文本、边界、强调、选中、焦点与危险状态的语义主题 token，MUST NOT（禁止）把具体颜色值散落在组件规则中。本变更 MUST（必须）以浅色主题验证结构和对比度，但 MUST NOT（禁止）把尚未确认的品牌颜色、字体或多主题视觉定为产品契约。

#### Scenario: 窄窗口不产生水平滚动

- **WHEN** 使用者把窗口缩小到无法容纳三栏常驻的宽度
- **THEN** 左分类与右检查器按规则折叠或覆盖，中央内容不出现水平滚动

#### Scenario: 更换主题不改组件布局

- **WHEN** 后续版本替换语义主题 token 的具体取值
- **THEN** 工作台组件无需修改布局或状态选择器即可呈现新主题

### Requirement: 原生事件订阅失败可见

应用 MUST（必须）显式呈现关闭保护与提示词拖放事件订阅失败，MUST NOT（禁止）静默退化为未保护或不响应的界面。错误必须保留上下文和原始原因；组件卸载后的失败不得更新过期界面。

#### Scenario: 关闭保护注册失败
- **WHEN** Tauri 关闭事件订阅拒绝
- **THEN** 应用显示持续可见的关闭保护失败说明，不宣称已获得保护

#### Scenario: 拖放订阅失败
- **WHEN** 提示词关联区拖放事件订阅拒绝
- **THEN** 关联区显示持续错误并停止宣称可拖入，显式按钮导入仍可用

#### Scenario: 草稿解决后继续关闭窗口
- **WHEN** 使用者关闭窗口时选择保存或放弃正文草稿
- **THEN** 主窗口通过明确授予的关闭权限继续关闭；关闭命令失败必须持续呈现原因

### Requirement: 备注保存状态适应重复挂载检查

备注编辑器 MUST（必须）在 React StrictMode 的 effect 重放后继续显示正在保存、成功和失败状态，且失败不清空草稿。

#### Scenario: 重放后保存失败
- **WHEN** StrictMode 内输入备注后保存接口拒绝
- **THEN** 当前草稿保持原文且显示错误码；再次保存成功后显示已保存

### Requirement: 两类瀑布流具有真实框选手势

图片和提示词瀑布流 MUST（必须）支持从空白处按鼠标主键拖框，按几何相交选择项目。Ctrl/Cmd 追加到手势开始前的选择；普通拖框替换选择。MUST（必须）保留活动项与键盘锚点；Esc 或 pointercancel 取消手势并恢复开始前选择。虚拟项不在 DOM 中不得导致漏选，且框选 MUST NOT（禁止）渲染全部项目。

#### Scenario: 普通与追加框选
- **WHEN** 用户从空白处拖出覆盖两个项目的矩形，或按 Ctrl/Cmd 拖框
- **THEN** 普通框选只选择相交项目，追加框选保留开始前选择并随矩形收缩移除本次不再命中的项目

#### Scenario: 跨滚动区域与取消
- **WHEN** 拖框期间滚动使项目卸载，或按 Esc 取消
- **THEN** 选择依据完整虚拟几何保持正确；取消恢复手势前选择且移除框线

### Requirement: 提示词聚焦入口与附属按钮隔离

提示词卡片和详情列表 MUST（必须）在双击项目或项目上按 Enter 时进入聚焦阅读。复制、收藏等附属控件的 Enter MUST NOT（禁止）连带触发聚焦。

#### Scenario: 两种视图进入与退出聚焦
- **WHEN** 在提示词卡片或详情列表项目上双击或按 Enter 后按 Esc
- **THEN** 先呈现对应提示词正文，再回到保留选择与滚动上下文的原集合

进入聚焦阅读 MUST（必须）显式接管键盘焦点，使实际键盘 Esc 而非仅程序派发事件可以退出。
