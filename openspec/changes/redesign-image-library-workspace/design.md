## Context

当前 Vistash 已经实现图片与提示词两个一级工作区、逻辑文件夹、标签、收藏、备注、回收站、多选、瀑布流、详情列表、检查器、全局搜索、布局记忆和 10,000 项虚拟化。它证明了 Rust 核心、SQLite 派生索引、Tauri IPC 和 React 行为契约可以工作，但前端仍带有验证性质：`App.tsx` 协调库状态、导入、工作区切换和全局定位，图片与提示词工作区各自超过 700 行，多个叶子模块直接依赖集中式 `shared/ipc.ts`，样式集中在一个全局文件中。

本变更不只是换皮。使用者确认了文件夹单一归属、目录层级导入、Windows 剪贴板导入、显示文件名、导出、默认程序打开和可停止长任务，这些决定会修改库格式、Rust 领域模型与 Tauri command。与此同时，提示词工作区必须保持可用，图像反推界面继续暂停。

设计服务于 Windows 优先、本地优先的单窗口桌面应用。素材库可能有数十 GB，但当前可度量界面规模仍为一次查询 10,000 条轻量记录；图片字节只按视口或显式预览读取。所有人类可读文案和注释使用简体中文，所有失败保持稳定错误码，不引入静默 fallback。

## Goals / Non-Goals

**Goals:**

- 建立图片优先、可长期使用的“高级媒体工作室”界面，并保持 Windows 原生窗口行为。
- 把图片管理收进单一公共入口的深模块，使应用外壳不再编排查询、选择、导入、检查器和缓存失效。
- 把旧版多文件夹素材安全迁移为零个或一个文件夹归属，不丢失使用者决策权。
- 为文件、目录、拖放、剪贴板导入和原图导出建立统一任务、进度、停止与错误语义。
- 保持提示词工作区的已批准行为，并通过导航与任务 seam 与图片模块协作而不共享内部 store。
- 先用可丢弃高保真原型确定品牌、布局和关键状态，再切换生产组件。
- 重构后继续通过 10,000 项虚拟化基线、键盘/可访问性检查和完整 Rust/前端门禁。

**Non-Goals:**

- 不实现图像反推、生图、provider 配置或提示词工作区视觉重构。
- 不实现智能文件夹、重复管理、评分、颜色旗标、EXIF 检索、相似搜索、AI 标签或图片编辑。
- 不实现文件系统监控、云同步、账号、原生拖出、批量重命名或通用素材操作撤销历史。
- 不把图片集合改成分页或无限查询；真实规模证明 10,000 项全量轻量元数据成为瓶颈前不增加协议。
- 不自绘 Windows 标题栏，不引入完整 Fluent UI、Tailwind、shadcn/ui、Redux、Zustand 或 React Router。
- 不建立图片与提示词共用的 `GenericCatalog<T>`、`Workspace<T>` 或为未来反推预留的空 port。

## Decisions

### 1. 先原型、后生产切换

在实现生产工作区前，使用固定假数据制作独立高保真原型，至少覆盖欢迎页、空库、瀑布流、详情列表、单选检查器、多选操作栏、灯箱、搜索、任务中心、设置以及深浅主题关键状态。原型不调用 Tauri IPC、不修改真实库，也不默认成为生产依赖。

原型通过评审后，把最终品牌资产、token、布局、断点和交互状态补回本设计与任务，再以纵向切片实现生产模块。旧界面只在开发分支中作为行为参照；新工作区达到功能、测试和性能等价后一次切换入口，并删除旧组件、旧全局样式和被新 interface 取代的浅层测试。正式构建不保留 legacy 开关。

备选方案是直接在当前组件上精修。该方案会让视觉试验与库格式、状态架构同时发生，难以判断回归来自设计还是行为，因此拒绝。

#### 原型评审结论：选择 A — Archive Desk

2026-08-25 的第一轮主工作区评审在三套可切换高保真方案中选择 A — Archive Desk 作为唯一生产设计基线。生产界面 MUST（必须）保留以下方向：

- 原生 Windows 标题栏下方使用紧凑应用顶栏，不改变系统窗口行为。
- 宽屏使用稳定的“左侧档案导航—中央图片墙—右侧纵向检查器”三栏结构，图片墙获得主要面积。
- 采用深石墨表面、精细单像素分隔、单一暖珊瑚强调和克制阴影；图片本身承担主要色彩。
- 瀑布流卡片默认弱化文字，悬停或选中时才增强显示文件名与尺寸；选中边界必须清晰且不遮挡图片。
- 文件夹、筛选、排序、密度、视图切换、任务和批量操作保持可见且紧凑，不把核心能力藏进多层菜单。
- 检查器保持连续纵向分区，图片摘要、色卡、组织和备注形成从视觉到管理的自然顺序。

B — Darkroom Strip 不作为主工作区，因为底部信息台和极大联系表会压缩文件夹、批量组织与持续检查器；C — Curator Ledger 不作为主工作区，因为编辑画册式构图降低大规模素材整理密度。两者只保留为评审证据，不批准其组件、布局或代码直接进入生产。

本轮批准的是视觉方向与信息层级，不是原型实现。`app/src/prototypes/image-library` 仍为 throwaway implementation；生产模块必须按本设计的深模块 interface、错误语义、测试和可访问性要求重新实现。欢迎页、空库、设置、浅色主题和窄窗口将在 A 的语言下补齐后完成第二轮评审。

2026-08-25 的第二轮评审确认 A 的欢迎页、空素材库、设置 Dialog、同结构浅色主题与窄窗口方案全部沿用。欢迎页使用“本地视觉档案”叙事与明确的本地库承诺；空库在保留工作台结构的同时把导入、文件夹导入和粘贴作为唯一主引导；设置保持有限范围；浅色主题只替换语义 token，不改变信息架构。第二轮仍未批准 prototype implementation 直接复用，最终应用图标、字体文件和图标包继续由任务 1.4 单独冻结。

#### 原型最终验收基线

原型评审证据保存在 `app/artifacts/prototype-image-library/`，覆盖 A/B/C 主工作区以及 A 的欢迎、空库、设置、浅色、多选、品牌与 760×760 窄窗口截图。自动检查同时验证详情列表切换、灯箱 `Esc` 返回、关键文字对比度、Tab 焦点、减少动态效果和无水平溢出。

生产实现冻结以下视觉与可访问性基线：

- 1440×900 是宽屏主参考；宽度大于 1050 px 时保持三栏，781—1050 px 时左栏收为图标导航，780 px 及以下时右检查器通过覆盖抽屉进入，中央区不得水平滚动。
- 常规 UI 文本不得小于 12 px，次级元数据不得小于 11 px；10 px 仅限不承载操作含义的装饰性英文 eyebrow。prototype 中为截图密度使用的 6—9 px 字号不得直接复制进生产。
- 普通文本、导航、主按钮和选中状态的目标对比度至少 4.5:1；Tab 焦点使用至少 2 px 的高可见轮廓，不得只靠颜色变化。
- hover/选中反馈使用 160—220 ms；栏位与 Dialog 状态变化不超过 240 ms。`prefers-reduced-motion: reduce` 下非必要动画与过渡时长降至近零，任务进度仍保留非位移状态变化。
- 多选时瀑布流、底部上下文操作栏和右侧批量检查器必须同时反映同一选择集合；文件夹动作始终写“移动”，不得恢复为多归属“加入”。
- prototype implementation、远程 Picsum 假图、状态切换器、B/C 方案和生成联系表全部拒绝进入生产 bundle；批准的只有信息层级、标识几何、token 和交互结论。

重构后的 10,000 项性能门禁固定为：瀑布流首屏不超过 350 ms，初始集合 DOM 不超过 24、快速滚动峰值不超过 40，快速滚动平均双帧不超过 20 ms、最坏不超过 35 ms，稳定 heap 不超过 60 MiB、视图切换后不超过 65 MiB，瀑布流/详情列表切换不超过 50 ms。任何超门禁项必须先诊断，不能靠增大阈值完成任务。

### 2. 三个纵向深模块与唯一公共出口

前端建立 `library-lifecycle`、`asset-library`、`prompt-library` 三个纵向模块。每个模块只允许从 `index.ts` 导入，`internal/` 是 implementation，不属于其他模块可依赖的 interface。

图片模块的公开 interface 保持窄小：

```ts
export type OpenLibrarySession = {
  id: LibraryId;
  displayName: string;
};

export type AssetLibraryEntry =
  | { kind: "resume" }
  | {
      kind: "locate";
      requestId: string;
      hash: AssetId;
      location: "active" | "trash";
    };

export type AssetLibraryWorkspaceProps = {
  session: OpenLibrarySession;
  active: boolean;
  entry?: AssetLibraryEntry;
};

export function AssetLibraryWorkspace(
  props: AssetLibraryWorkspaceProps,
): React.ReactElement;
```

`library-lifecycle` 负责欢迎、开库、损坏/版本失败、迁移计划、冲突处理和切库，只有完成兼容性门禁后才产生 `OpenLibrarySession`。图片模块内部拥有查询、选择、文件夹、标签、检查器、灯箱、导入导出、布局偏好、TanStack Query key、虚拟化和图片 URL 生命周期。

备选方案一是顶层平铺 `import/`、`export/`、`folders/`、`selection/` 等 feature；删除任何一个后编排复杂度都会回到 `App.tsx`，属于浅模块，因此拒绝。备选方案二是公开无头 `AssetLibrarySession` 的完整 Snapshot/Intent/Command；当前没有第二种宿主，这会为假想 seam 冻结巨型 interface，因此拒绝。

### 3. 导航、内部任务协调、全局搜索与平台 adapter 是应用级 seam

图片和提示词都真实需要跨工作区定位、长任务状态协调和全局搜索，因此 `WorkspaceNavigation`、`TaskCenter`、`GlobalSearch` 是应用层拥有的窄 interface。`TaskCenter` 当前只作为内部 store，不提供全局浏览界面。它们必须使用判别联合或明确方法，禁止演化为无类型全局 Event Bus。

Tauri 是项目自有的跨进程依赖。生产使用 `TauriPlatformAdapter`，测试使用 `MemoryPlatformAdapter`，因此这是具有两个 adapter 的真实 seam。adapter 负责 command/channel/event/对话框/剪贴板/默认程序与媒体租约的传输映射；产品规则、自动重试、缓存失效和默认值不进入 adapter。

图片与提示词的普通关联继续通过后端用例完成。两个 UI 模块不得互相导入内部组件、query key 或 store；关联变更通过权威写入结果与模块级失效事件协调。

### 4. TanStack Query 只管理异步 IPC 状态

使用 TanStack Query 管理库状态、集合快照、详情、全局搜索和 mutation。QueryClient 在应用组合根创建，图片模块隐藏自己的 key 工厂与失效规则。key 必须包含 `libraryId`，默认 `retry` 为 `false`，关闭窗口聚焦和网络重连触发的无条件全库刷新，并给历史筛选查询设置有限 `gcTime`。

选择、活动项、框选锚点、灯箱、面板和输入草稿使用 React state、reducer 与模块内部 Context。布局偏好继续通过后端持久化。mutation 成功后由图片模块精确失效集合、详情、计数或关联查询；删除 `catalogVersion`/`refreshVersion` 这类穿透外壳的刷新协议。

备选方案是 Redux/Zustand 统一管理全部状态，它会混合权威异步数据与短生命周期 UI 状态，且当前不存在需要第二个 store adapter 的 seam，因此拒绝。

### 5. Radix Primitives、内部 UI 模块与 CSS Modules

复杂可访问交互选择 Radix Primitives，按实际需要安装 Dialog、AlertDialog、Popover、DropdownMenu、ContextMenu、Tooltip、Select 与 ScrollArea 等包。Vistash 自己实现 Button、IconButton、SearchField、Toolbar、Panel、EmptyState、Progress、Toast 等无业务 UI 模块；`FolderTree`、树内新建表单和文件夹移动目标表单作为图片/提示词共用的无业务 UI，`AssetCard`、`AssetInspector` 与 `SelectionBar` 留在图片模块内部。

样式使用全局 `reset.css`、`tokens.css`、`globals.css` 与模块级 `.module.css`。token 表达表面、文本、边界、强调、选中、焦点、状态、间距、圆角、阴影、动效、层级和字体，业务规则禁止散落具体主题色。图标只选择一套；具体字体、强调色和图标包在高保真原型评审后冻结。

完整 Fluent UI 虽能提供 Windows 熟悉度，但会显著限制 Vistash 的品牌差异；Tailwind/shadcn 会引入新的样式与生成约定，而当前需要可审查的长期组件 interface，因此均不采用。

### 6. 自定义标题栏、直接恢复与响应式三栏

Tauri 主窗口设置 `decorations: false`，应用内顶栏同时承载紧凑品牌、库切换器、一级入口、全局搜索、导入、设置和窗口控件。中间剩余空白区使用 Tauri `data-tauri-drag-region`；所有交互子节点都不带拖动属性。窗口按钮通过 `@tauri-apps/api/window` 调用 `minimize`、`close`，最大化按钮先读取 `isMaximized()` 再显式调用 `maximize()`/`unmaximize()`，capability 与这些动作一一对应。实机拒绝继续使用在当前 Windows 无边框窗口上只能最大化、无法稳定还原的 `toggleMaximize()`。整体遵循 Tauri v2 官方 Window Customization 流程，不自建 Rust 窗口 IPC。

库切换器放在品牌与一级工作区之间，按钮主文案是当前库目录名，浮层内显示完整路径、“新建素材库”和“打开其他库”。图片“导入”只向当前库添加素材，不承担切库。原图片导航顶部的重复库名删除。`LibraryLifecycleControls` 直接提供 `createNewLibrary/openOtherLibrary`；调用原生目录选择器时保留当前 context，取消后不再跳到 Welcome。只在新路径通过兼容性门禁后才替换 session key，借此卸载旧库媒体租约并恢复新库布局。

已有可用库时直接恢复上次工作现场，不增加首页；首次运行和库失败由 `library-lifecycle` 接管。

宽屏保持左分类、中央集合、右检查器三栏；中等宽度把左栏变为按需导航，窄宽度把右栏变为覆盖抽屉，中央区始终优先。图片与提示词分别持久化栏宽、折叠、查询、排序、视图和滚动；图片额外保存缩略图尺寸与检查器分区状态。具体断点由原型在目标窗口尺寸上验证后写入 token，不成为业务组件中的魔法值。

### 7. 深浅主题和轻量品牌系统

主题提供 `system`、`dark`、`light` 三值偏好，默认 `system`，监听 Windows 主题变化。深色石墨主题是主视觉，浅色使用温和中性表面；二者共用 DOM、组件状态和语义 token。系统减少动态效果时取消非必要位移、缩放和视差，仅保留即时状态过渡。

品牌阶段重做应用图标、紧凑字标、一种强调色和 UI/展示字体组合。参考分工为 Eagle 的素材密度、Lightroom 的暗色图片工作台、Linear 的交互精度、Are.na 的档案气质和 Windows 的窗口/键盘习惯，不复制任何单一产品，也不采用营销页 Hero、滚动叙事、玻璃发光或满屏胶囊。

#### 品牌评审结论

2026-08-25 品牌板评审确认以下基础：

- 应用标识使用“叠放档案框＋负形 V”。两层框体表达本地档案，实心 V 同时指向 Vistash 与观看视野；禁止回到通用山峰、太阳、镜头光圈或图片占位符。
- 主色固定为 Archive Black `#111313`、Graphite `#171919`、Bone `#ebe7dd` 与 Signal Coral `#e8664a`。Status Green `#6e9b73` 只表示成功或健康状态，不作为第二品牌强调色。
- Windows UI 字体栈使用 `Bahnschrift, "Microsoft YaHei UI", sans-serif`。Bahnschrift 负责拉丁字符、数字和紧凑技术气质，Microsoft YaHei UI 负责简体中文小尺寸界面；不随应用重新分发 Microsoft 字体文件。
- 展示字体栈使用 `Georgia, SimSun, serif`，只用于欢迎页、集合标题和少量品牌语句，MUST NOT（禁止）进入表格、表单、标签和用户长文本。
- 唯一通用图标系统使用 `@phosphor-icons/react`，默认 `regular` weight，活动收藏等填充状态使用 `fill`。从具体 CSR 文件路径导入实际使用图标，MUST NOT（禁止）整包命名空间导入或混用 Lucide、Radix Icons、Unicode 符号和 Emoji。
- 原型 SVG `app/src/prototypes/image-library/assets/vistash-icon-concept.svg` 是品牌几何的评审证据。生产任务必须从批准几何生成无 BOM SVG 源、Tauri PNG/ICO 全尺寸资源并逐个检查 16、32、64、128、256 与 512/1024 px；不得直接把 prototype 路径变成生产依赖。

选择 Windows 内置 UI 字体而不是打包完整 CJK Web Font 是有意的：素材名称、标签和备注可能包含任意中文，完整覆盖字体会显著增加安装包；Windows 官方把 Microsoft YaHei UI 定义为简体中文界面字体，而产品的独特性由展示字体、间距、图片主导结构、标识和颜色共同承担。

### 8. 素材侧车升级为单归属与显式来源

新库格式把旧版 `original_filename` 与多值文件夹字段迁移为显式结构。概念形状如下，最终 Rust 类型名称可按现有领域命名调整：

```rust
enum AssetSource {
    Filesystem {
        path: Option<PathBuf>,
        filename: String,
    },
    Clipboard {
        captured_at: DateTime<Utc>,
        filename: String,
    },
}

struct AssetMetadata {
    source: AssetSource,
    display_filename: String,
    folder: Option<LogicalFolderPath>,
    // 其余既有权威字段保持显式。
}
```

文件系统导入把来源路径与来源文件名写入 `Filesystem`；v2 允许来源路径缺失，迁移时必须保留为显式 `path: null`，MUST NOT（禁止）伪造路径或用默认字符串顶替。位图粘贴生成带本地时间的 PNG 名称，同时记录 UTC 捕获时间。显示文件名是必填字段，不使用读取时 fallback；迁移明确把旧原始文件名复制到来源与显示字段。扩展名由真实媒体格式拥有，重命名只修改名称主体。

单归属文件夹把“移动”变成唯一写操作，目标为 `None` 时表示未分类。标签继续多值。旧版多归属数据不能靠取第一项解决。

### 9. 迁移使用计划、暂存、提交和恢复日志

旧库打开后先只读扫描侧车并生成迁移计划。无冲突项自动得到确定映射，多归属项必须完成唯一目标选择。确认前不写任何权威文件。

提交时在库内创建带唯一 ID 的迁移工作目录，只暂存库级元数据、文件夹树、侧车与恢复日志，不复制素材本体。流程为：

1. 校验计划仍对应当前库版本、全部侧车摘要和 `folders.json` 原始字节摘要；文件夹清单或侧车发生变化都必须重新规划。
2. 写完全部新侧车与新库级元数据到暂存区。
3. 写恢复日志并把旧权威元数据备份到同卷迁移目录。
4. 逐项原子替换权威元数据。
5. 删除并从新元数据重建 SQLite 派生索引。
6. 校验不变量后更新迁移日志为完成，再清理备份。

任一步失败都按恢复日志把旧元数据放回并保留旧格式版本。进程在提交期间异常退出时，下次开库必须先检测未完成日志并执行恢复，不能猜测当前文件属于新旧哪一代。迁移进入替换阶段后不提供取消；冲突选择与确认前可以退出。

### 10. 四种入站来源汇入同一 Rust 导入协调器

文件选择、目录选择、拖放与剪贴板只负责产生 `ImportSource`，之后进入同一 Rust 协调器。文件导入到当前具体逻辑文件夹；当前是全部、未分类或回收站时进入未分类。文件夹导入以当前具体文件夹为父级，否则从逻辑根开始，并保留所选目录名与相对层级。

路径规范化在写入前完成；同逻辑路径合并。目录中的非图片计入跳过结果。重复内容不复制，也不移动既有素材。扫描、哈希、复制、解码、缩略图、色卡、侧车和索引继续在窗口线程之外执行。

每个长任务拥有 `TaskId` 和库级 `concurrencyKey`。停止通过真实后端命令设置取消状态；扫描阶段尽快观察，处理阶段在单素材事务边界观察。已成功素材保留，当前素材成功或回滚，后续项记为未处理。

### 11. Windows 剪贴板全部留在 Rust/platform seam

资源管理器复制的文件列表通过 Windows `CF_HDROP` 读取完整路径；生产 adapter 使用 Microsoft `windows` crate 的 `OpenClipboard`、`GetClipboardData`、`DragQueryFileW` 与 RAII `CloseClipboard` guard，并只启用 `Win32_Foundation`、`Win32_System_DataExchange`、`Win32_System_Ole`、`Win32_UI_Shell` 和 `Win32_Storage_FileSystem` 等实际所需 features。打开剪贴板失败必须返回稳定的 `clipboard.busy`，不得冒充空剪贴板。句柄内容在 `CloseClipboard` 前立即复制成自有 `PathBuf`，目录扫描和解码只能在关闭剪贴板后开始。

第一阶段只支持具有真实文件系统路径的 `CF_HDROP`，明确排除依赖 `CFSTR_FILEDESCRIPTOR`/`CFSTR_FILECONTENTS` 的 Shell 虚拟文件。即使剪贴板来自“剪切”，Vistash 也只复制进库，绝不执行源文件移动或删除。

截图或应用复制的位图由 Rust blocking worker 直接读取 Windows `CF_DIBV5`/`CF_DIB`。`OpenClipboard` 期间只读取固定头、在尺寸与像素上限内复制确切 DIB 字节，RAII guard 关闭剪贴板后才逐像素解码、编码 PNG 并进入现有哈希与导入管线；畸形 `GlobalSize` 不得在头校验前触发整块复制。支持 24-bit `BI_RGB` 与 32-bit `BI_RGB`/`BI_BITFIELDS`，其他压缩格式返回稳定的 `clipboard.image_invalid`。前端只提交“从剪贴板导入”意图，不接收 RGBA、`ImageData` 或其他像素缓冲。文件列表优先于位图，纯文本和网址不处理。WebView 不获得通用剪贴板读取权限，只获得 Vistash 领域 command；官方插件继续只用于 Rust 侧写出图片。

窗口级 `Ctrl+V` 只在图片模块 `active` 且事件目标不属于可编辑控件时认领。文本框、搜索框和备注编辑器保持原生粘贴。文件/目录选择继续使用官方 `tauri-plugin-dialog`，但由窄 Rust command 直接接收结果并开始导入，避免把任意选择路径扩大成 WebView 文件读取 scope。

一手资料与本机最小验证记录在 `research/windows-platform-integration.md` 和 `app/scripts/prototype-windows-platform-check.ps1`。验证在不修改系统剪贴板的情况下构造 `DROPFILES` 内存并由 `DragQueryFileW` 往返两条 Unicode 路径，同时验证只读删除拒绝、占用删除拒绝与位图 PNG 编码。

### 12. 导出、复制图像与默认程序打开不暴露哈希库布局

导出由 Rust 读取权威索引确定本体路径，并用显示文件名与真实扩展名复制到使用者选择的目录。同名冲突先生成冲突计划，使用者明确选择跳过、覆盖或自动编号后才写入。覆盖必须二次确认；报告逐项隔离失败，并支持在单文件边界停止。

“复制图像”只允许单张图片，由 Rust 解码并写入 Windows 位图剪贴板。多选不合成图片。

“使用默认程序打开”不直接把内容哈希对象交给可能写回的外部程序。Rust command 在 `app_cache_dir()/external-open/v1/<session-id>/` 创建使用显示文件名和真实扩展名的只读副本，写入只含相对文件名、素材 ID、创建时间与版本的 manifest，再通过官方 `tauri-plugin-opener` Rust `OpenerExt` 调用 Windows 默认关联程序。WebView 不获得素材库或任意磁盘路径的 `openPath` scope；外部修改只影响副本。界面不提供“在资源管理器中显示”内部哈希对象。

`openPath` 返回不代表外部程序已经释放文件，且 Shell 可能复用既有进程而不给出可等待的进程句柄，因此禁止立即删除副本。当前 session 运行期间不清理自身目录；应用启动时只处理非当前 session、具有有效 manifest 且创建超过 24 小时的目录。清理前移除 Vistash 设置的只读属性；`ERROR_SHARING_VIOLATION` 表示外部仍占用，必须保留并在下次启动重试；其他错误显式记录。清理前必须解析绝对路径并证明目标仍位于 `app_cache_dir()/external-open/v1/`，不得沿 junction、符号链接、reparse point 或 manifest 外路径递归删除。

### 13. 内部任务协调只聚合，不拥有业务事务

`TaskCenter` 记录任务 ID、种类、库作用域、并发键、状态、节流进度和完成报告。图片模块拥有导入、导出和批量操作的业务协调；内部任务记录不能决定回滚、重试或缓存失效，也不直接渲染全局入口。切换一级工作区不卸载任务状态，异常反馈由发起区域拥有。

状态至少区分 `running`、`stopping`、`stopped`、`succeeded`、`partial`、`failed`。只有后端确认后进入 `stopped`。成功且无需处理的记录可结束为内部终态；部分成功、停止或失败由发起区域持续呈现到使用者明确关闭。

反馈分层为字段附近的就地错误、短暂成功 Toast、稳定任务报告和不可逆操作 Dialog。未知协议或不变量错误继续抛给应用级错误边界，禁止 catch-log-rethrow 或通用“操作失败”兜底。

### 14. 集合保持全量轻量记录与真正虚拟化

本变更继续使用一次查询返回当前结果全部轻量行的 IPC。TanStack Query 只有限缓存历史筛选；缩略图、原图、详情、色卡和关联数据按需读取。瀑布流和详情列表继续使用 `@tanstack/react-virtual`，仅为视口与过扫窗口创建 DOM。

媒体接口返回显式租约：

```ts
export type ImageLease = {
  url: string;
  release(): void;
};
```

租约隐藏 Blob URL 或未来 asset protocol 的差异，并由图片模块在项卸载、换源、预览关闭、LRU 淘汰和切库时释放。重构后的 10,000 项基线不得明显劣于当前约 295 ms 瀑布流首屏、12 个初始项 DOM、22 个峰值项 DOM、47.5 MiB heap 和 37 ms 视图切换；具体允许回归阈值在原型冻结布局后写入任务验收数据。

分页只在真实 50,000/100,000 规模测量证明元数据传输、排序或内存成为瓶颈后另立变更。图片模块 interface 不暴露当前是否分页。

### 15. 选择、检查器和灯箱共享一个模块内 session

选择集合只保存素材 ID，活动项必须属于选择集合。瀑布流和详情列表共享查询、排序、选择、活动项和滚动恢复。多选采用 Windows 习惯：单击、`Ctrl+单击`、`Shift+单击`、`Ctrl+A`、框选与 `Esc`；底部上下文操作栏提供移动、标签、收藏、关联和回收站操作，右键菜单只作快捷入口。

检查器使用纵向可折叠分区而非互斥 Tab。灯箱覆盖当前窗口，按当前查询顺序导航相邻素材，缩放和平移只用标准图像渲染与 CSS transform，不读取像素。退出后恢复原滚动位置并把最后查看素材设为活动项。

### 16. 测试通过模块 interface 与真实平台验收

生产 Tauri adapter 和内存 adapter 必须满足同一领域 port contract。图片工作区行为测试从 `asset-library/index.ts` 的公开 interface 渲染，验证查询、选择、导入意图、批量结果、迁移闸口和任务反馈；不在每个叶子组件 mock 数十个 `invoke` 函数。纯瀑布流几何、选择算法和迁移计划可保留模块内部 seam 的确定性测试，但调用者测试不得穿透内部目录。

### 18. UI 基础审查补充验收

2026-08-27 的 Hallmark 只读审查发现四项已由用户批准修复的问题。沿用既有 `LibraryLifecycle`、`SearchField`、`SettingsDialog` 和 `Button` 公开界面测试边界，不引入新的状态架构、依赖或品牌方案。

- 迁移页明确限定为可用视口高度，中间冲突列表独立滚动；组件展台同样建立有界滚动容器，其固定高度示例面板须约束内部 ScrollArea，不得让列表溢出并覆盖相邻空状态。拒绝只增大窗口或放开全局 body 滚动掩盖问题。开发专用展台通过内存 port 提供 60 项真实冲突计划，由真实组件渲染并操作，不以复制 DOM 作为修复验收。
- 搜索输入预留固定清除槽位；鼠标或键盘激活清除后把焦点交回输入。保持已批准的 Escape 清空语义，不把清除按钮隐藏时的空间回收当作视觉效果。
- 主题选项保留现有三张选项卡外观，改用同组原生 radio，方向键由浏览器处理。显式使已选项 `tabIndex=0`、未选项 `tabIndex=-1`，让 Radix Dialog 按 tabIndex 枚举焦点边界时也只识别已选项；真实回归验证从弹窗首项反向 Tab 不会落到未选项。拒绝仅添加 `role="radio"` 而缺少行为，也不为三个选项新增组件库依赖。
- 紧凑文字按钮使用现有 12px `--text-size-sm`；高度与间距仍紧凑，11px 元数据 token 不变。
- 先建立失败回归再改行为；布局、原生 radio 键盘默认动作在 Windows 浏览器实测，jsdom 只覆盖其能准确表达的公开行为。覆盖 1440×900、760×600、深浅主题；全部选择完成前迁移仍不可提交，页面调整不改变迁移事务。

已知根因已在上一轮浏览器探针中定位，本轮以正式失败检查确认，不重新进行无目标的假设搜索。清除临时调试改动；验收脚本、开发 fixture 与复验证据纳入项目，记录见 `validation/ui-foundation.md`。

### 19. 图片会话切片的真实契约与实施顺序

任务 8.2 沿用第二条的 `AssetLibraryWorkspace` interface；查询、定位去重、选择、偏好与 key 全部封装在 `internal/`。已有 8.1 测试必须与生产传输一致：`catalog_snapshot` 只接收 query，查询 Rust 当前已打开的库；`libraryId` 进入 Query key 与 `read_layout`/`write_layout`，不向现有 command 塞入后端不会读取的参数。测试在同一 QueryClient 中切换后端当前库，验证重名哈希也不串库。切库先经过 library-lifecycle，旧会话卸载；非活动工作区不发起新查询或消费定位。

- 布局继续使用已有 `assets`/`prompts` JSON 分区，本阶段严格验证已消费的六个查询/视图字段，其余已有栏宽、滚动等字段原样保留。不把损坏字段补默认值；只有 read_layout 返回 null 才建立首次使用的默认查询。后续栏位与密度控件在各自任务中接入。
- 布局编辑立即更新本库缓存，写入使用同库串行 mutation；每次落盘前读取最新根对象，只替换图片分区，避免覆盖提示词或其他未消费字段。读失败阻止恢复，写失败保留本地状态并显示稳定错误，允许使用者显式重试；没有自动重试。

- 新模块不接收 `catalogVersion`/`refreshVersion`。已批准的生产切换时点仍为 11.3：在最终切换前旧 App 保持可运行，旧外壳协议与旧界面届时一并删除，禁止增加 legacy 运行时开关。

备选方案是让测试虚构带库 ID 的 command，或直接包裹旧 AssetWorkspace；前者无法证明真实契约，后者继续依赖旧刷新与全局样式，均拒绝。使用已安装 TanStack Query 的 mutation scope 进行写序列化，使用 TanStack Virtual 的 lanes 和按画幅估算高度进行窗口化；不增加依赖。几何与选择测试仍通过已有批准的 seam，不新增对外 session store。

本阶段完整门禁同时修正已有 Dialog 公开 interface 测试的异步等待：Radix FocusScope 在卸载后的定时任务恢复焦点，测试须等待同一焦点断言成立，不能立即把 body 上的过渡状态判作失败。不改 Dialog 生产行为，也不修改 worker、超时或调度配置。

### 21. 显示文件名编辑与来源信息

9.2 沿用 `asset-library/index.ts` 的公开界面测试接缝。F2、工具栏与检查器共用受控编辑 Dialog；打开时冻结素材哈希、当前显示名、来源名和真实扩展名，防止异步刷新把草稿套到另一张图片。只允许对当前查询中唯一选中的正常图片编辑；多选、回收站、查询占位数据、非活动工作区及其他输入框/弹层不认领 F2。

输入框仅包含名称主体，扩展名单独只读显示。已有 v3 元数据必须满足后端的真实扩展名约束；不猜测缺失字段、不修改来源名或哈希对象。合法性仍由 Rust `rename_asset_display_filename(hash, stem)` 裁决，前端不复制 Windows 文件名规则。提交失败保留草稿与稳定错误码，只有成功后才精确失效本库集合及目标详情。显示名与来源名搜索沿用现有后端查询，不在 React 过滤图片列表。

右侧先落地文件身份区，后续 9.3 补齐其余检查器分区；窄窗口可从“图片信息”进入覆盖式 Dialog，同一信息区复用。选择弹窗而不是失焦自动保存，避免临时输入在切换图片时触发权威写入，也不引入额外草稿 store。

通用 Dialog 只新增可选的打开/关闭焦点回调，既有调用默认行为不变。F2 打开时聚焦并全选名称主体；关闭后恢复触发位置。若重命名使素材退出当前查询，回到搜索框，禁止焦点落到已卸载卡片。编辑仍使用既定主题与模块边界，不新增依赖、原生命令或库格式。

### 22. 单选检查器的分区与草稿所有权

9.3 使用连续六分区：摘要、色卡、组织、备注、关联提示词、文件信息。分区标题为可键盘操作的展开按钮，顶部分区定位同时展开目标并移动焦点；不采用互斥 Tab。布局的可选 `inspectorSections` 字典只记录使用者明确覆盖的展开状态，未覆盖分区默认展开；已出现的键和值必须严格校验，不修补损坏值。保存仍合并本库图片布局，不覆盖提示词偏好。

详情按库身份和图片哈希读取，过期请求不能覆盖新活动项；正常图可编辑，回收站只读。组织复用现有移动、标签、收藏命令；普通关联候选按需查询正常提示词，已删除关联保留标记。跨工作区定位与联动仍在 11.1 验收，不提前增加不可用入口。

备注保留纯文本、800ms 停顿、失焦和 Ctrl+Enter 保存语义。图片模块内部以 QueryClient 生命周期和库身份隔离短期备注会话，草稿按哈希保存，不进入异步查询缓存或磁盘布局。切图、收起分区、关闭窄屏检查器均不丢失失败草稿；同图写入串行，旧请求不得覆盖新输入。切库/停用时取消尚未发出的定时写入并保留未保存文本，禁止卸载后向后端新当前库补写；返回后由明确编辑或保存动作继续。错误保持就地可见，不自动重试。

宽窄呈现共用一个备注会话与详情 key，不创建两份自动保存协调器。继续使用已有媒体租约，摘要不读取原图像素；色卡只展示 Rust 结果和真实失败码。拒绝复制旧检查器的全局样式、跨库草稿键或错误 fallback，不增加依赖和 Rust command。

### 23. 多选检查器与固定目标的批量编辑

9.4 从当前查询和选择 ID 派生选中图片，不另存一份选择状态。多选检查器只展示数量、共同或混合的文件夹/收藏/格式/尺寸、共同标签和部分图片标签，不展示活动图片的文件名、色卡或备注。标签计数按图片计数；多选不发起逐图详情或图片字节读取。摘要与底部操作栏共享同一组 ID，视图切换不重置它。

移动、收藏与回收站复用已有动作协调器；添加/移除标签和建立普通提示词关联接入现有批量 IPC。标签编辑和关联选择使用工作区拥有的受控 Dialog，打开时固定素材 ID；即使成功项退出筛选、多选变单选或清空选择，编辑会话及逐项结果仍保留。部分失败后锁定本次编辑意图，只允许重试失败 ID 或关闭；整个请求失败则保留输入供修正。普通批量组织不提供虚假的停止按钮。

通用 Dialog 支持省略内部 trigger，供检查器与底部栏两个可见入口打开同一个编辑会话；关闭由工作区恢复到实际触发位置，触发控件消失时回到仍存在的检查器或集合搜索。单选编辑不在多选工具栏冒充批量收藏。

同库组织写入期间禁止再次提交，成功或部分成功后精确失效当前库集合、目标详情和需要更新的关联候选。回收站多选仅展示只读摘要，还原与清空界面仍在 9.5 实施。拒绝引用旧 BatchOrganizer、用标签并集冒充共同标签或逐图读取详情汇总；不改变公开工作区 interface、依赖、库格式或 Rust command。

### 24. 回收站还原、永久清空与权威状态刷新

9.5 沿用现有 `restore_asset` 与 `purge_trash`，不新增库格式或 IPC。单选检查器、回收站多选检查器和底部栏提供还原入口；一次还原固定目标 ID 与显示文件名，逐项调用现有单图事务并分别保留成功、缺失原文件夹、失败和切库后未处理结果。组件卸载后禁止继续发出下一项请求，不将未处理项冒充失败或成功，也不提供虚假的用户停止按钮。

删除前唯一文件夹由 Rust 权威侧车决定。现有轻量行的 `folder` 在删除后被清空，不能把它显示成“原文件夹”；回收站界面说明还原将恢复删除前位置，不猜测原位置。`missing_folders` 明确表示已恢复到未分类的成功附带提示，不把它算作还原失败。

永久清空使用阻断式确认，明确删除整个图片回收站、包含当前筛选未显示的图片、无法还原。只有确认后才读取无筛选回收站快照并调用清空；完整快照用于按哈希保留显示名，因为现有 `PurgeFailure` DTO 只带来源名。映射失败必须显式报错，不用来源名静默代替。清空前读取失败不执行删除；切库后也不得继续提交清空。

还原或清空的成功、部分失败和整体错误都刷新本库集合与相关详情/关联候选，以显示真实剩余项。尤其清空可能在删除后重建索引时报错，界面不得承诺“全部未删除”。结果保持在不随选择栏卸载的回收站报告区域；错误可以再次操作，但永久删除每次都要重新确认。清空导致按钮禁用时把焦点交回集合搜索，窄屏还原后关闭覆盖检查器可返回原入口。

回收站报告按 QueryClient 生命周期和库身份保存在模块内部订阅状态中；切库后返回仍可查看旧请求的结果，关闭报告才移除，不把报告塞进服务端查询缓存。延续 Archive Desk、既有深模块边界和同库组织 mutation 范围。普通删除仍是移入库内回收站而非永久删除；回收站组织信息继续只读。完整内部任务协调仍属于 10.3，不提前勾选该任务。

### 25. 大图灯箱与浏览现场恢复

10.1 在当前窗口内使用 Radix Dialog 呈现全尺寸灯箱，不调用原生全屏，也不改变 Windows 标题栏。集合双击或无修饰键 Enter 进入单图浏览；打开时固定当前查询的有序轻量记录，按该顺序切换相邻图片，首尾不循环。关闭后选中最后查看的图片，保留查询、视图、排序与打开前的集合滚动位置；最后图片在原视口外时聚焦集合容器，不为聚焦强行滚动。新的外部定位、停用工作区或切库关闭旧灯箱。

原图仅通过已有 `acquireOriginal` 租约读取。每次切图/重试拥有独立请求身份，旧请求迟到时立即释放，不显示到新图片；换源、关闭及切库释放已取得的租约。错误保留稳定错误码与明确重试/关闭入口，不以缩略图冒充原图；浏览器无法显示已取得字节时使用明确的前端 `viewer.decode_failed`，不伪装成导入失败。

适合窗口保持完整画幅且不放大小图；100% 按 Rust 元数据固有尺寸对应 CSS 像素渲染，Windows DPI 由 WebView 处理。按钮、滚轮按有界比例缩放（最大 800%），拖动仅平移超出视口的部分，边界约束保证图片不会被拖丢。普通左右键切图，Shift+方向键平移，Home 适合窗口、1 恢复 100%、加减键缩放。背景选择深色、浅色或棋盘格，使用独立媒体表面 token，不改变全局主题。

尺寸来自容器观察和已有图片元数据，缩放/平移仅用 img 与 CSS transform；禁止 Canvas 像素处理。拖动与滚轮高频工作局限于灯箱内部，不刷新集合查询。打开灯箱期间暂停集合自动聚焦，返回请求显式恢复滚动和焦点，避免虚拟列表把最后图片滚到新位置。继续按公开模块 interface 测试，不新增生产依赖或 Rust command。

### 26. 统一图片入站与内部任务协调接线

10.2 使用已有 `PlatformPort` 的 Tauri adapter 作为唯一入站传输边界，补充独立的 `pickImportDirectory` 对话框语义，避免把库位置选择器误当成导入目录。图片工作区内部只调用 `appPlatform`：文件选择得到路径数组，文件夹选择得到单个目录，剪贴板只提交意图；三者都进入同一个导入协调函数并传入当前具体逻辑文件夹，全部不读取源文件字节。

应用级运行时由 `app/runtime.ts` 创建一次 `appPlatform` 与 `appTaskCenter`。图片模块保留窄公共 interface，不把平台或内部任务协调塞入 `AssetLibraryWorkspace` props；同一 store 只负责跨工作区并发和终态事实，不接入 `AppShell` 可见入口。每次导入先注册 `TaskKind="import"`、库级传输并发键和可停止标志，再把后端进度映射到内部状态；重复导入只返回稳定 `transfer.already_running`，不静默排队。

内部任务记录使用 TaskCenter 生成的应用任务 ID；收到首个传输进度后保存后端 `task_id`。停止协议只在存在该 ID 时可调用：先进入 `stopping`，后端返回 `stopped` 且导入结果到达后才调用 `confirmStopped`，停止失败不冒充已停止。导入完成报告由图片工作区就地呈现成功、跳过、失败和尚未处理，失败显示来源文件名与错误码。

整窗口拖放只在真实 Tauri window/webview metadata 存在时订阅 `PlatformPort.onFileDrag`；普通浏览器开发入口不伪造原生拖放环境，因此不会因部分 Tauri mock 对象而白屏。工作区级 Ctrl+V 只在活动且目标不是 input/textarea/select/contenteditable/Dialog/Menu 时认领，备注和搜索保持原生粘贴。空集合同时保留“没有符合条件的图片”和导入引导，按钮复用同一协调器。

备选方案是让 `App.tsx` 继续接收路径、进度和刷新版本，或让每个导入按钮各自调用 IPC；前者会把旧外壳协议带入新模块，后者会分裂重复与失败语义，均拒绝。当前导入报告由图片工作区就地呈现；停止协议与冲突对话在 10.3 继续扩展，不增加全局任务浏览界面或第二套任务 store。

### 27. 传输内部状态与图片出站操作

导入与导出共享应用级 `appTaskCenter` 和库级传输并发键。图片模块在同一个 transfer handle 中保存应用任务 ID、后端 task ID、停止请求与后端确认；内部 store 只记录状态，不决定事务，也不渲染全局停止按钮。结果到达且后端返回 `stopped` 后才进入 stopped，成功、跳过、失败、未处理和逐项错误明细保留在内部记录与发起区域报告中。

图片出站工具只在有选中素材时呈现：单选提供复制位图和默认程序打开，多选不合成图片，只提供原图导出。导出先用 `plan_export` 做只读冲突规划；跳过、自动编号和覆盖是明确的统一决议，覆盖再经过阻断式二次确认才提交 `export_assets`。导出与导入一样按素材边界报告失败和未处理项，完成后提供短暂成功状态；复制和默认程序打开失败使用就地稳定错误，成功反馈不替代任务报告。目标目录由独立的导出目录选择器取得，既不复用库位置也不把哈希库布局暴露给 WebView。

出站控制与空集合引导共用 Archive Desk token 和既有 Button/Dialog/Popover。复制与打开的入参形状分别是单个 `AssetId`，因此多选合成在类型和界面两端都被排除；所有长任务共享同一内部协调，并在各自发起区域观察异常结果。

### 29. 操作显隐由频率与当前上下文决定

2026-08-29 第二轮实机反馈确认：功能全部常驻不是“可发现”，而是把导入、查询、单图操作、批量操作和检查器导航混成同一视觉层级。生产界面按“始终需要、当前上下文需要、低频但必须可达”三层收敛，不能再用增加文字按钮解决可发现性。

- 顶栏“导入”只保留需要主动选取目标的图片和文件夹；剪贴板属于系统粘贴能力，由工作区的 `paste`/`Ctrl+V` 入口认领，不在菜单或空库引导重复成按钮。工作区必须即时显示正在读取、空内容、重复、成功或稳定错误反馈。

- 只有选择至少两张图片时才显示底部批量栏。常用的移动、标签和收藏保持直接入口；关联提示词和移入回收站收进同一“更多操作”菜单。收藏只显示与当前集合状态相符的一个动作，不同时出现“收藏”和“取消收藏”。

### 2026-08-29：图片浏览范围与文件夹树交互纠偏

左栏把“全部图片、收藏、未分类、具体文件夹、回收站”画成同一组导航，但旧状态模型把收藏当成独立可叠加轴，导致从收藏返回全部图片后仍携带 `favorite=true`，出现标题显示全部图片而集合为空的语义冲突。纠偏后这五类入口是互斥浏览范围：入口原子写入 `folder`、`favorite` 与 `location`；中央搜索和标签仍保持可叠加。选择范围与筛选维度因此在代码和视觉上使用同一词汇。

子文件夹属于已批准领域能力，不新增物理目录。文件夹节点增加右键菜单，直接承载“新建子文件夹、重命名、移动、删除”；侧栏标题旁的显式按钮继续作为发现性与键盘等价入口。文件夹拖动与图片拖动使用不同的内部载荷：前者重设完整逻辑子树的父路径，后者只修改素材的唯一文件夹归属。

文件夹重设父路径新增 `move_folder(source, destination_parent)` 深命令。核心层先验证源、目标父节点、禁止自身/后代目标与目标路径碰撞，再复用文件夹重命名已有的子树 rebase、侧车批量写入和事务回滚机制；Tauri 只翻译字符串与进度 Channel。拖放和“移动文件夹”Dialog 都调用同一命令，不在 React 中拼写或直接写侧车。备选方案是用 `rename_folder` 伪装移动，但该命令只接受最后一级名称，无法表达目标父节点且会让错误语义含混，因此拒绝。

### 2026-08-30：剪贴板与色卡可靠性纠偏

`favorite=false` 是“只看未收藏”，不是“清除收藏筛选”；全部图片、未分类、具体文件夹与回收站必须写入 `favorite=null`，只有收藏范围写入 `true`。旧偏好里的 `false` 在恢复时规范化为 `null`，任何左栏范围切换都只使用 null/true 两态。

剪贴板生产 adapter 以 Win32 标准格式判断并读取 DIB/DIBV5：没有位图不执行像素路径；存在但头、位深、压缩、掩码或缓冲非法时必须上抛，不再压成 Empty。2026-08-31 的真实 `Print Screen` 已证明插件 `read_image()` 在 Windows 报告 DIB 时仍可能 `ConversionFailure`，满足调研中“有失败证据才改为直读 DIB”的触发条件，因此删除读入插件路径，不维护两套读取 fallback。位图 PNG 编码直接读取已校验 RGBA 缓冲并使用快速压缩。色卡样本长边从 256 调整到 160、算法版本提升为 2；最大样本由 65,536 降到 25,600，保持八色与确定性测试，同时显著降低 debug App 的聚类成本。

历史失败不能靠提升算法版本自动改写权威侧车。新增 `regenerate_color_card(hash)` 深命令：读取正常区权威侧车与原图、用当前算法重算、原子写回侧车并更新派生索引。检查器失败态和旧版本态提供同一重算入口。成功呈现改为比例色带加紧凑图例；前端仍不接触像素。

### 2026-08-30：范围重置、反馈层与树层级

实机再次证明“导入成功但看不到”来自范围内残留标签：新图片没有当前标签，因此被查询排除。最终把左栏范围定义为完整范围切换，全部、收藏、未分类、具体文件夹和回收站均清空 text/tags；筛选仍可在进入范围后重新添加。导入目标继续只由当前具体文件夹决定，全部图片下为未分类。

操作反馈分层：进行中状态写入内部任务协调；空剪贴板和重复使用 Toast；整体失败与部分失败、缺失原文件夹、未处理目标在发起区域持续报告。纯成功不改变内容区高度。瀑布流说明从白色全宽底栏改为图片内部的 `surface-backdrop` 浮层。文件夹树以更大层级缩进、父节点打开图标和 CSS 分支线表达父子关系，不增加另一套数据状态。

### 2026-08-30：即时建夹、导入揭示与顶栏减法

导入成功回调现在根据触发时范围恢复可见现场：具体文件夹保持该路径；全部图片保持全部；收藏或回收站转到未分类；所有路径清空 text/tags/favorite。只有 `imported > 0` 才改变现场，空剪贴板和重复不跳转。

新建文件夹不再复用编辑 Dialog。侧栏标题 `+` 与节点右键“新建子文件夹”都在目标树位置挂载 `InlineFolderCreator`，父路径由挂载位置决定；输入框支持 Enter/确认、Esc/取消和失败原地保留。重命名、移动、删除继续属于节点上下文。

应用壳层删除 `TaskCenterPopover` 及其组合 props；内部 `appTaskCenter`、并发键、停止状态与失败记录继续由领域协调器使用。顶栏因此只保留品牌、一级入口、全局搜索、导入和设置。卡片悬浮信息进一步从带边框胶囊改为无边框渐隐层，与图片下缘融合。
- 检查器分区本身已经是可折叠且可键盘操作的导航，因此删除顶部重复的“摘要/色卡/组织/备注/关联提示词/文件信息”定位栏。摘要不重复解释肉眼可见的状态；色卡失败显示人类可理解的摘要，稳定错误码作为展开详情而非主文案。
- 标签统一为轻量 chip：名称与计数分开，选中使用填充态；检查器标签带明确移除图标，添加表单只保留“标签”字段与图标按钮，不用三处重复“添加图片标签”。

本轮不增加新的图标包，继续只从 `@phosphor-icons/react/dist/csr/*` 导入。图标不是装饰替代文字：熟悉动作可只显示图标，领域动作保留短文案；所有图标按钮必须通过 Tooltip 和 `aria-label` 提供名称。拒绝为每个低频动作创建新浮层，也拒绝把危险操作仅做成无差别图标。

### 30. 栏位偏好与详情列表收尾

12.4 把此前只在设计中声明、尚未接入控件的栏位字段正式解释为图片模块偏好：`navigationWidth` 默认 216、范围 176—320px；`inspectorWidth` 默认 288、范围 256—420px；`navigationCollapsed` 与 `inspectorCollapsed` 默认 `false`。字段缺失表示旧布局并注入默认值；字段存在但类型错误或超界必须拒绝读取，不静默夹取损坏配置。

宽屏使用可聚焦的竖向 separator 调整栏宽，鼠标拖动期间只更新本地呈现，Pointer Up 才写一次布局，避免每像素产生 IPC；方向键每次 8px，Home/End 到边界，双击恢复默认值。两栏都提供明确的收起/展开图标。1050px 以下继续由断点把左栏自动收为图标导航，780px 以下检查器继续使用覆盖 Dialog；自动响应式状态不覆盖使用者保存的宽屏折叠偏好。

详情列表继续复用当前虚拟集合、查询、选择与滚动，不引入第二套列表。每行呈现缩略图、显示文件名、唯一文件夹、标签、尺寸、格式、导入时间与备注摘要，并提供同序列列标题。宽度不足时按“备注→导入时间→标签→文件夹”的优先级隐藏低优先列，名称与尺寸始终保留；完整值保留在 title/可访问文本中，不请求逐图详情或图片字节。

### 31. 标签计数、文件夹顶层移动与连续详情表

左栏标签的主任务是选择词汇，不是展示统计表。`TagUsage.count` 继续保留在快照与按钮可访问名称中，但不再作为无分隔的可见尾字符；这样新增标签不会看起来被自动改名为“标签1”。备选方案是继续显示独立徽标，但当前标签数量少且用量不参与决策，额外数字只会增加噪声，因此拒绝。

子文件夹层级使用缩进、Folder/FolderOpen 图标和连续竖向引导，删除容易被误认成名称字符的 L 形横杠。已嵌套节点的右键菜单直接提供“移到顶层”，并以 `destinationParent=null` 复用现有深命令；通用移动 Dialog 把旧根位置文案改为“顶层（无父文件夹）”并显示结果路径。不新增 Rust 命令或元数据语义。

详情列表仍复用同一虚拟化 canvas，但视觉上从“多个悬浮圆角卡片”收敛为一个连续数据表面：列头与列数据共用网格，行只用底部细线分隔，缩略图置于固定方形容器，格式与标签使用低对比辅助形态。悬停只改背景，选中使用浅强调面和左侧强调线，不改变行高、边框宽度或列位置。这一设计沿用现有 token、Phosphor 图标和亮/暗主题，不增加第二套设计系统。

### 32. 稳定瀑布流滚动几何与提升超长图缩略图

真实 1280×800 Tauri 回收站以 CDP 连续取样 120 帧：瀑布流集合 `clientWidth` 在 714/699px、`clientHeight` 在 581/566px、卡片宽度在 230/225px 之间循环，横向溢出固定为 15px；同一结果切到详情列表后 120 帧只有一组几何且溢出为 0。根因是 `overflow: auto` 下纵向滚动条改变内宽，ResizeObserver 使卡片宽和原画幅高度重算，总高再使滚动条反向切换。

集合滚动容器改为 `overflow-x: hidden; overflow-y: auto; scrollbar-gutter: stable`：横向滚动不是产品能力，因此禁止而不保留；纵向滚动条不论是否出现都保留同一 gutter，ResizeObserver 始终看到稳定可用宽度。备选方案是常驻可见纵向滚动条，但在空集合/短列表上额外引入视觉噪声，故拒绝。

回收站 `676×1726` 原图的旧缩略图为 `201×512`，实际卡片为约 `223×569`，因此 q=80 WebP 在降采样后又被放大。灯箱读取 `676×1726` 权威原图并缩小显示时清晰，证明原图未损坏。缩略图长边从 512 提高到 1024，该超长图得到约 `401×1024` 派生图；格式版本从 2 提升到 3，下次开库只清空旧缩略图树，后续按视口需要从原图重算。这会提高派生存储和首次重算成本，但不修改权威原图、侧车或索引；两档缩略图会增加命名、清理与租约复杂度，当前 10,000 项门禁还没有证据需要该分层，因此不在本次引入。

首次升级实机还暴露旧 `ensure_thumbnail(lib, hash, ext)` 无法表达权威本体位置：旧缩略图存在时该缺口被遮蔽，换代清空后回收站素材错误地去 `objects/` 找本体。新接口使用明确的 `ThumbnailSource::Active/Trash`；Tauri command 从 Catalog 索引取得删除状态后传入，重建器只读对应树。备选的“正常路径不存在就试回收站”会在权威对同时存在两处时隐藏损坏，违反项目的严禁 fallback 规则，因此拒绝。

### 33. 查询占位数据只稳定导航，不冒充新范围内容

完整用户路径“全部图片→移动到文件夹→点击文件夹”的公开工作区回归证明：Query Key 包含完整 folder query，单图/批量操作都失效当前库的 collection family，Rust 使用 `FolderSelection::Exact`，完成查询只返回直接成员。用户观察到的“还是全部图片”发生在新查询等待阶段：TanStack Query 的 `placeholderData: previous` 把上一查询快照传给新 key，旧卡片与旧数量继续被渲染。大库、刚完成批量写入或首次重建缩略图时，这个过渡足够长，会被理解为文件夹筛选失效。

保留 `placeholderData` 来稳定左栏文件夹树、标签词表和回收站数量，但把 `collection.isPlaceholderData` 定义为中央内容不可呈现状态：标题已使用新 layout，数量改为“正在读取…”，卡片/列表卸载并呈现“正在读取图片…”。新查询完成后再替换成真实成员。备选的完全删除 placeholder 会让左栏文件夹与标签在每次切换时闪空，产生另一个导航跳动，因此拒绝。

### 34. 文件夹拖动期间显式揭示顶层放置区

旧实现理论上允许把文件夹拖到树容器的空白处并提交 `destinationParent=null`，但实际节点覆盖了大部分树面积，标题和导航空白又不属于命中区域；使用者无法发现也难以稳定命中。图片与提示词改为复用同一个显式顶层放置区：只有文件夹拖动激活时，它出现在文件夹树首行，文案为“移到顶层”，带 Tray 图标；命中时使用强调面和边框反馈，松开仍调用各自已有的移动深命令。

备选方案是扩大整个侧栏空白为根目标。它会让指针离开文件夹列表时仍可能意外提交，且没有可见提示，因此拒绝。右键“移到顶层”和移动 Dialog 继续作为键盘与精确操作入口。

### 35. 文件夹拖动在越过阈值后才捕获指针

真实 App 在导入 `1. 照片` 后出现“点击文件夹没有作用”：权威侧车、文件夹清单、导入时间和全部图片排序均正确，但完整鼠标序列只有 `pointerdown`，没有 `pointerup/click`。根因是共享 `useFolderTreeDrag` 在按下瞬间对导航栏调用 `setPointerCapture`；浏览器把后续 pointerup 重定向给导航栏而非原按钮，因此不生成 click。jsdom 测试过去直接调用 `.click()`，绕过了 Pointer 生成规则并掩盖问题。

修正后 pointerdown 只记录来源和起点；pointermove 首次超过 6px 阈值时才捕获指针并进入拖动态。普通点击不捕获，完整保留 `pointerdown → pointerup → click`；真实拖动仍依靠捕获跨节点移动并可命中顶层放置区。备选的“同时在 pointerup 手工触发 onClick”会制造键盘/鼠标双触发并绕过按钮语义，因此拒绝。

### 36. 导入结果由传输模块拥有持续反馈

移除顶栏任务入口后，`AssetTransfer` 仍把完整 `ImportOutcome` 交给内部任务存储，但界面只呈现拖入状态，`outcome.failures` 和本地 `error` 没有消费者。导入反馈必须由发起传输的深模块自己拥有：纯成功不占空间；部分失败或未处理项转换为稳定的本地报告队列，列出计数、来源显示名和错误码，并允许使用者逐份明确关闭。报告以 `LibraryId` 隔离并保存在模块级会话存储中，新任务与切到其他库后的组件重挂载都不得清理；只有对应关闭动作移除。Toast 只补充空剪贴板、重复或整次 IPC 失败的即时提醒，不代替报告。

导入与导出复用一个按 `LibraryId` 隔离的可订阅报告存储；报告身份由模块生成，类型区分 `import`/`export`，停止状态使用 `completed | stopping | stopped` 判别值。导入控制器和导出协调器只追加完整 `TaskOutcome`：已请求但尚未确认时先记录 `stopping`，只有后端返回 `stopped` 后才原位更新为 `stopped`；即使停止恰好发生在最后一项、未处理数为零，也必须保留可关闭报告。工作区级反馈负责呈现完成桶、停止状态与明确关闭，因此切换选择、卸载检查器或切到其他素材库都不会丢失或串库。失败项列表使用报告 ID 与条目序号组成 React key，不把可能重复的显示名或错误码冒充身份。

备选是恢复全局任务中心。它违反已经批准的顶栏减负和就地错误分层，因此拒绝。报告转换、保留与呈现集中在图片传输知识簇，调用者不复制第二套持久状态。

## Risks / Trade-offs

- [Risk] 单归属文件夹会改变既有库语义，错误迁移会永久丢失组织信息 → 迁移先只读规划，多归属必须人工选择，使用同卷暂存、恢复日志和整体回滚，提交前不修改原库。
- [Risk] 新 change 同时包含视觉重构与后端新增能力，范围较大 → 任务按库格式、platform seam、应用基础、图片纵向切片和最终切换排序，每个任务完成测试后立即勾选，原型先冻结视觉变量。
- [Risk] 深模块内部可能再次长成难以导航的巨型文件 → 唯一公共出口保持窄小，内部按 session、collection、organization、transfer、media 等真实知识簇组织，并通过公开 interface 做主要行为测试。
- [Risk] `TaskCenter` 或导航演化成无类型事件总线 → 只接受明确判别联合与固定作用域，不允许任意字符串主题或业务 payload。
- [Risk] TanStack Query 缓存多个 10,000 项结果增加内存 → key 包含库身份，历史查询使用有限 `gcTime`，媒体字节不进入集合 cache，并复测 heap。
- [Risk] Windows 剪贴板、默认程序和文件对话框无法仅靠浏览器测试覆盖 → platform adapter 隔离，内存 adapter 做确定性测试，release Tauri 构建执行 Windows 层验收。
- [Risk] 默认程序可能改写库内哈希对象 → 只打开应用管理的只读临时副本，不把权威本体路径交给外部程序。
- [Risk] 导入停止响应过慢 → 扫描循环与每个素材事务边界观察取消状态，内部状态在后端确认前保持 `stopping`。
- [Risk] 原型代码被无审查复制进生产并形成第二套架构 → 原型与生产目录、依赖和数据源隔离，评审只批准设计决策；复用任何代码必须由对应实施任务明确批准。
- [Trade-off] 保留全量轻量记录避免当前没有证据的分页复杂度，但不面向 100,000 项承诺 → 维持 10,000 项门禁，并让模块 interface 隐藏查询实现以便未来替换。
- [Trade-off] 暂不提供通用撤销，误操作恢复不如专业 DAM 完整 → 永久删除二次确认，回收站可还原，组织操作反馈明确；可靠撤销历史另立规格。

## Migration Plan

1. 完成并严格校验本 change；在修改生产行为前冻结 delta specs、迁移不变量与适配器 interface。
2. 制作独立高保真原型，评审并把最终品牌 token、断点、关键布局和性能阈值补入设计与任务。
3. 先在 Rust 建立新库格式、显式来源/显示文件名、单归属 folder、只读迁移计划和恢复日志；用 fixture 验证无冲突、多冲突、写入失败和进程中断恢复。
4. v3 侧车字段与单归属操作先只通过其公开 interface 验证；在迁移提交、恢复日志和打开门禁完成前，生产 `AssetSidecar` 别名、Catalog、SQLite 索引与批量命令继续使用 v2，禁止形成“新阅读器已启用但旧库无法迁移”的中间状态。
5. 迁移门禁完成后，用迁移后的 v3 fixture 验证索引重建、双文件名查询与 Catalog 单归属事务，再一次切换生产别名、SQLite、Catalog 和批量命令。
6. 建立 platform ports、Tauri/Memory adapters 与内部任务协调，不切换现有生产工作区。
7. 实现目录/剪贴板导入、停止、导出、复制图像和默认程序临时副本，并完成 Windows 验收。
8. 建立 UI token、Radix 基础模块、应用外壳和 `library-lifecycle`；随后按集合、组织、检查器、灯箱、传输和任务状态完成 `asset-library` 纵向切片。
9. 用新模块公开 interface 重建行为测试，验证提示词入口和关联行为未回归；复测 10,000 项性能与深浅主题/键盘/窄窗口。
10. 达到功能与门禁等价后切换 `App.tsx` 到新模块，删除旧图片工作区、旧浅层刷新协议和被替代样式；不保留运行时 legacy 开关。
11. 运行全部四类项目门禁、Windows release 验收、OpenSpec strict validate 与最终 code review。

若生产切换前失败，可继续使用旧界面和旧格式 fixture；一旦真实库成功迁移到新格式，不提供应用内降级写回。迁移事务本身失败时按恢复日志回到旧格式，应用二进制回滚必须使用仍支持旧格式的版本。
