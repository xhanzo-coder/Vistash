## ADDED Requirements

### Requirement: 图片导航使用互斥浏览范围

图片导航中的“全部图片、收藏、未分类、具体文件夹、回收站”MUST（必须）表示彼此互斥且完整的浏览范围，MUST NOT（禁止）把上一范围的收藏、文件夹、文本或标签条件静默叠加到新范围。切换任一范围时 MUST（必须）清空文件名搜索与标签筛选，保证“全部图片”真的包含全部正常图片、具体文件夹展示该节点全部直接成员。重复点击当前范围 MUST（必须）保持幂等。

左栏标签名 MUST（必须）作为唯一主要可见文本；素材使用数 MAY（可以）作为辅助提示或可访问名称，但 MUST NOT（禁止）无分隔地拼在标签名后，使 `速速速` 显示成像 `速速速1` 的新名称。

切换互斥浏览范围后、新范围查询尚未完成时，左栏 MAY（可以）继续使用上一快照的文件夹树和标签词表保持导航稳定，但中央集合 MUST（必须）立即停止呈现上一范围的图片与数量，并显示“正在读取图片…”。MUST NOT（禁止）把“全部图片”旧快照冒充为新文件夹的直接成员。

#### Scenario: 从收藏返回全部图片

- **WHEN** 使用者先进入“收藏”再点击“全部图片”
- **THEN** 查询清除收藏、文件夹、搜索与标签条件并展示全部正常图片

#### Scenario: 从收藏进入未分类

- **WHEN** 使用者先进入“收藏”再点击“未分类”
- **THEN** 查询清除收藏、搜索与标签条件并只展示没有文件夹归属的正常图片

#### Scenario: 从文件夹进入收藏

- **WHEN** 使用者正在浏览 `参考/构图` 后点击“收藏”
- **THEN** 查询清除文件夹、搜索与标签条件并展示全库收藏图片

#### Scenario: 新增单次使用的标签

- **WHEN** 使用者新增标签 `速速速` 且当前只有一张图片使用它
- **THEN** 左栏主文本显示 `速速速`，不把计数 `1` 伪装成标签名的一部分

#### Scenario: 移动素材后进入目标文件夹

- **WHEN** 使用者在“全部图片”把素材移到 `配色`，随后点击 `配色`，而新查询仍在读取
- **THEN** 标题立即变为 `配色`，中央区显示读取状态且不显示全部图片旧卡片；完成后只显示精确归属 `配色` 的素材

### Requirement: 文件夹层级和卡片信息具有明确视觉归属

左侧文件夹树 MUST（必须）通过明显缩进、父节点图标和连续的竖向层级引导区分层级，MUST NOT（禁止）让父文件夹与子文件夹看起来处在同一平面，也 MUST NOT（禁止）在子节点名前放置看似名称字符的孤立横杠。文件夹标题处 MUST（必须）只保留新建入口；重命名、移动和删除 MUST（必须）属于具体节点的上下文菜单。

瀑布流卡片的文件名与尺寸 MUST（必须）作为图片内部的轻量浮层出现，MUST NOT（禁止）使用占满卡片宽度的白色底栏把原画幅截成上下两块。普通操作成功 MUST NOT（禁止）在集合底部持久追加结果条；只有失败、缺失目标或未处理项可保留报告。

#### Scenario: 查看父子文件夹

- **WHEN** `wada` 下存在子文件夹 `构图`
- **THEN** `wada` 使用父节点图标，`构图` 有明显缩进与连续竖向引导，名称前没有孤立横杠，二者仍可独立选择

#### Scenario: 悬停瀑布流图片

- **WHEN** 使用者悬停、聚焦或选中一张瀑布流图片
- **THEN** 文件名和尺寸以图片内部浮层出现，不增加白色卡片底栏高度

#### Scenario: 普通操作成功

- **WHEN** 收藏、移动、还原或剪贴板导入完整成功
- **THEN** 集合布局不出现纯成功持久结果条；内部任务记录保留事实，必要的空内容或重复提示使用短暂 Toast，失败或未处理项在发起区域持续呈现直到明确关闭

### Requirement: 色卡可以重新分析且优先表达色彩关系

色卡 MUST（必须）由 Rust 侧从库内权威原图重新解码和分析，前端 MUST NOT（禁止）读取像素。检查器 MUST（必须）允许对失败或旧算法色卡发起重新分析，成功后原子更新侧车与派生索引；重算仍失败时 MUST（必须）显示人类可理解的原因和稳定错误码，不得永久卡在没有恢复入口的历史失败状态。

色卡呈现 MUST（必须）以连续比例色带表达主要色彩关系，并以紧凑图例补充色号、角色和占比；MUST NOT（禁止）继续使用八行等权色块表格让次要颜色获得与主色相同的视觉权重。

#### Scenario: 重新分析历史失败色卡

- **WHEN** 一张不透明图片的旧侧车记录 `color_card.insufficient_opaque_pixels` 且使用者选择重新分析
- **THEN** Rust 重新读取权威原图并以当前算法写入新的色卡，图片本体和其他元数据保持不变

#### Scenario: 真正透明的图片仍无法分析

- **WHEN** 图片可参与分析的不透明像素仍低于当前算法下限
- **THEN** 检查器说明可见像素不足、保留稳定错误码并允许稍后重试，不伪造颜色

#### Scenario: 查看成功色卡

- **WHEN** 色卡包含主色和多个次要色
- **THEN** 检查器首先显示按占比组成的连续色带，再显示紧凑色号与角色图例

### Requirement: 可编辑显示文件名与不可变来源文件名

每个图片素材 MUST（必须）保存不可变的来源文件名与可编辑的显示文件名。导入时显示文件名 MUST（必须）初始化为来源文件名；剪贴板位图 MUST（必须）获得包含本地时间且在当前导入中唯一的 PNG 显示文件名。修改显示文件名 MUST NOT（禁止）重命名内容哈希对象或修改来源文件名。

使用者 MUST（必须）只能编辑名称主体，真实扩展名 MUST（必须）由素材格式决定。素材列表和检查器 MUST（必须）优先呈现显示文件名，并 MUST（必须）在文件信息区保留来源文件名。导出 MUST（必须）默认使用显示文件名与真实扩展名。

#### Scenario: 重命名普通素材

- **WHEN** 使用者把 `IMG_0042.JPG` 的显示文件名改为 `雨夜街道`
- **THEN** 界面与默认导出名变为 `雨夜街道.jpg`，来源文件名仍为 `IMG_0042.JPG`，内容哈希对象路径不变

#### Scenario: 拒绝伪造扩展名

- **WHEN** 使用者尝试把 PNG 素材的名称主体输入为 `参考图.jpg`
- **THEN** 界面不把素材伪装成 JPEG，并要求只提交合法名称主体

#### Scenario: 重命名失败保留输入

- **WHEN** 使用者提交显示文件名后权威侧车写入失败
- **THEN** 编辑控件保留尚未保存的名称并显示稳定错误码

### Requirement: 单归属文件夹库格式迁移

打开允许多文件夹归属的旧版库时，系统 MUST（必须）先生成只读迁移计划。零个文件夹归属的素材 MUST（必须）迁移为未分类，一个归属 MUST（必须）原样保留；多个归属 MUST（必须）列为冲突并要求使用者为每个素材选择唯一文件夹。系统 MUST NOT（禁止）自动选择第一个、最深层或其他猜测结果，也 MUST NOT（禁止）把额外文件夹静默转换成标签。

全部冲突得到明确选择且使用者确认前，系统 MUST NOT（禁止）修改库文件。提交迁移 MUST（必须）升级库格式版本并以整个迁移为回滚单元；任一权威文件或索引步骤失败时 MUST（必须）恢复旧库完整状态。

#### Scenario: 无冲突旧库自动迁移

- **WHEN** 旧库中所有素材都只有零个或一个文件夹归属
- **THEN** 迁移计划无需人工冲突选择即可提交，并保留全部原有组织信息

#### Scenario: 多归属冲突要求选择

- **WHEN** 某素材同时属于 `参考` 与 `配色`
- **THEN** 迁移界面显示该素材及两个原归属，并在使用者选择唯一文件夹前禁止提交

#### Scenario: 迁移失败整体回滚

- **WHEN** 提交迁移时某个素材侧车写入失败
- **THEN** 库格式版本、全部侧车、文件夹树与索引恢复到迁移前状态

## MODIFIED Requirements

### Requirement: 逻辑文件夹路径与层级操作

文件夹 MUST（必须）使用以 `/` 分隔的逻辑路径表示层级，MUST NOT（禁止）映射为库内物理目录。路径的每一段 MUST（必须）在去除首尾空白后非空，MUST NOT（禁止）包含 `/`、控制字符、`.` 或 `..` 段；规范化后的完整路径 MUST（必须）在库内唯一。

创建子文件夹时其父文件夹 MUST（必须）已经存在。重命名文件夹 MUST（必须）同时重命名全部后代路径及所有素材侧车中的唯一文件夹归属。把文件夹移动到另一个父节点或库根位置时 MUST（必须）移动完整子树并同步更新素材归属，MUST NOT（禁止）把文件夹移动到自身或自身后代，也不得覆盖已有目标路径。删除文件夹 MUST（必须）删除该文件夹及其后代逻辑节点，但 MUST NOT（禁止）删除任何素材；归属于被删子树的素材 MUST（必须）变为未分类。

每个文件夹节点 MUST（必须）提供右键上下文入口以新建子文件夹、重命名、移动和删除；已嵌套节点 MUST（必须）另外提供直接的“移到顶层”入口，不得要求使用者猜测“库根位置”的含义。同一能力 MUST（必须）具有可见或键盘可达的等价入口。拖动文件夹时，文件夹树顶部 MUST（必须）出现明确的“移到顶层”放置区，并在指针命中时给出高亮；拖动文件夹到另一文件夹或该放置区 MUST（必须）分别以目标路径或 `destinationParent=null` 移动完整子树。拖动素材到文件夹与拖动文件夹重组树 MUST（必须）使用可区分的载荷和反馈，禁止把两者混为同一操作。

文件夹拖动处理 MUST NOT（禁止）在 `pointerdown` 时立即捕获指针；只有移动距离越过拖动阈值后才可捕获。未越过阈值的按下与松开 MUST（必须）完整归属于文件夹按钮并产生普通点击，使点击文件夹可以切换精确查询范围。

文件夹清单和受影响素材侧车的批量变更 MUST（必须）具备回滚：任一权威元数据文件写入失败时，操作 MUST（必须）恢复全部已写文件并返回明确错误，不得留下只完成一部分的重命名或删除。

#### Scenario: 创建一个子文件夹

- **WHEN** 使用者在既有 `参考` 文件夹下创建名称为 `构图` 的子文件夹
- **THEN** 文件夹清单新增唯一逻辑路径 `参考/构图`，磁盘上不建立同名素材目录

#### Scenario: 拒绝非法文件夹名称

- **WHEN** 使用者提交空白名称、`.`、`..`、含 `/` 或控制字符的名称
- **THEN** 系统返回 `library.folder_invalid`，文件夹清单与素材元数据均不改变

#### Scenario: 重命名含后代和素材的文件夹

- **WHEN** `参考` 下存在 `参考/构图` 且两个路径均有素材，使用者把 `参考` 重命名为 `灵感`
- **THEN** 文件夹路径变为 `灵感` 与 `灵感/构图`，全部相关素材的唯一归属同步更新

#### Scenario: 移动文件夹子树

- **WHEN** 使用者把 `参考/构图` 移动到既有 `项目 A` 下
- **THEN** 文件夹路径变为 `项目 A/构图`，全部后代路径及相关素材的唯一归属同步更新

#### Scenario: 把子文件夹移回顶层

- **WHEN** `wada/构图` 的右键菜单中选择“移到顶层”
- **THEN** 系统以 `destinationParent=null` 提交子树移动，结果路径为与 `wada` 同级的 `构图`

#### Scenario: 把子文件夹拖回顶层

- **WHEN** 使用者开始拖动 `wada/构图` 并把指针移到文件夹树顶部出现的“移到顶层”放置区后松开
- **THEN** 放置区在命中时高亮，系统以 `destinationParent=null` 提交子树移动，结果路径为顶层 `构图`

#### Scenario: 普通单击文件夹不被拖动手势吞掉

- **WHEN** 使用者在文件夹节点按下并在未移动超过 6px 的情况下松开
- **THEN** 指针仍由原文件夹按钮接收并产生 click，中央集合切换为该文件夹的精确成员

#### Scenario: 拒绝把文件夹移动到自身后代

- **WHEN** 使用者尝试把 `参考` 移动到 `参考/构图` 下
- **THEN** 系统返回 `library.folder_invalid`，文件夹清单与素材侧车均不改变

#### Scenario: 删除含素材的文件夹子树

- **WHEN** 使用者确认删除 `参考` 文件夹及其后代
- **THEN** 文件夹节点被删除，素材本体不被删除，受影响素材全部变为未分类

#### Scenario: 文件夹批量写入中途失败

- **WHEN** 重命名文件夹时某个素材侧车写入失败
- **THEN** 文件夹清单和此前已写入的侧车恢复到操作前状态，并返回明确错误码

### Requirement: 素材文件夹成员关系

一个正常素材 MUST（必须）属于零个或一个逻辑文件夹；零个归属表示素材位于界面所称的“未分类”。把素材移动到文件夹时目标文件夹 MUST（必须）存在，成功后 MUST（必须）替换原文件夹归属；移动到未分类 MUST（必须）清除原归属。回收站素材 MUST NOT（禁止）被直接修改文件夹归属。

素材文件夹变更 MUST（必须）先原子写入素材侧车，再更新派生索引；索引写入失败 MUST（必须）被显式报告并通过重建恢复与侧车一致，MUST NOT（禁止）回写或猜测侧车内容。

#### Scenario: 把素材移动到另一个文件夹

- **WHEN** 某素材当前属于 `参考`，使用者把它移动到 `配色`
- **THEN** 素材只属于 `配色`，不再属于 `参考`

#### Scenario: 把素材移到未分类

- **WHEN** 使用者把素材移动到“未分类”
- **THEN** 素材仍正常存在且侧车不记录文件夹归属

#### Scenario: 拒绝不存在的目标文件夹

- **WHEN** 使用者把素材移动到一个不在文件夹清单中的路径
- **THEN** 系统返回 `library.folder_not_found`，素材侧车保持不变

### Requirement: 文件名、标签与文件夹组合查询

素材查询 MUST（必须）支持文件名文本、零个或多个标签、一个文件夹位置与正常/回收站位置。文件名文本 MUST（必须）同时对显示文件名和来源文件名按 Unicode 小写转换后执行子串匹配；空文本不限制结果。选择多个标签时素材 MUST（必须）同时具有全部所选标签。选择文件夹时 MUST（必须）只返回唯一归属于该精确路径的素材；选择未分类时 MUST（必须）只返回没有文件夹归属的素材。

正常查询 MUST NOT（禁止）返回回收站素材，回收站查询 MUST（必须）忽略正常文件夹条件并只返回已删除素材。结果 MUST（必须）继续按导入时间倒序并以哈希作为稳定决胜字段。

#### Scenario: 按显示文件名大小写不敏感搜索

- **WHEN** 素材显示文件名为 `Character-Sheet.PNG` 且使用者搜索 `character`
- **THEN** 该素材出现在结果中

#### Scenario: 按来源文件名找到已改名素材

- **WHEN** 素材来源文件名为 `IMG_0042.JPG`、显示文件名为 `雨夜街道`且使用者搜索 `img_0042`
- **THEN** 该素材仍出现在结果中

#### Scenario: 组合两个标签

- **WHEN** 使用者选择标签 `人物` 与 `逆光`
- **THEN** 结果只包含同时具有这两个标签的正常素材

#### Scenario: 查询未分类

- **WHEN** 使用者选择“未分类”且不输入其他条件
- **THEN** 结果只包含没有文件夹归属的正常素材

#### Scenario: 查询回收站

- **WHEN** 使用者进入回收站并输入文件名文本
- **THEN** 结果只在已删除素材中按显示文件名或来源文件名过滤，不混入正常素材

### Requirement: 删除与还原操作保持素材对完整

删除素材 MUST（必须）把本体与更新了删除状态的侧车成对移入库内回收站，并 MUST（必须）删除正常树中的旧侧车。删除过程任一步失败 MUST（必须）回滚本次已完成的移动或写入，使素材最终完整地处于正常树或回收站之一，MUST NOT（禁止）同时存在于两处或只剩本体/侧车之一。

还原素材 MUST（必须）把本体与侧车成对移回正常树，清除删除状态，并恢复删除前的唯一文件夹归属。若原文件夹已不存在，素材 MUST（必须）变为未分类并显式返回缺失路径。还原任一步失败 MUST（必须）回滚到完整的回收站状态。

删除与还原完成后 MUST（必须）更新派生索引；删除后的提示词记录保持不变。

#### Scenario: 删除一个已归档素材

- **WHEN** 使用者删除属于 `参考` 的素材
- **THEN** 本体和侧车成对进入库内回收站，侧车记录删除前文件夹 `参考`，正常查询不再返回该素材

#### Scenario: 删除中途写入失败

- **WHEN** 本体已经移入回收站但更新后的侧车写入失败
- **THEN** 本体回到正常树，原侧车保持有效，索引仍把素材视为正常素材

#### Scenario: 还原时原文件夹缺失

- **WHEN** 素材删除前属于 `已删除文件夹` 且还原时该路径已不存在
- **THEN** 素材恢复为未分类，界面明确列出缺失的 `已删除文件夹`

#### Scenario: 还原中途失败

- **WHEN** 还原本体后写入正常侧车失败
- **THEN** 本体和侧车恢复为完整回收站状态，正常树中不留下部分产物

### Requirement: 图片瀑布流、详情列表与固定检查器

图片库中央区 MUST（必须）提供保留原始画幅比例且可调整缩略图尺寸的瀑布流，以及以缩略图、显示文件名、图片文件夹、标签、尺寸、格式、导入时间与备注摘要为列的详情列表。详情列表 MUST（必须）呈现为单一连续的数据表面，使用稳定列对齐、轻量分隔和清楚选中态，MUST NOT（禁止）把每行做成互相悬空的大圆角卡片。两种视图 MUST（必须）共用同一查询、排序、选择集合与活动项，切换视图 MUST NOT（禁止）清空当前上下文。

瀑布流滚动容器 MUST NOT（禁止）产生横向滚动，并 MUST（必须）为纵向滚动条保留稳定占位，禁止因滚动条出现/消失导致虚拟列宽、卡片高度和总滚动高度在连续帧中来回切换。缩略图派生数据 MUST（必须）在当前支持的卡片密度与 Windows 高 DPI 下不被放大为低于 1:1 源像素比；调整缩略图尺寸或编码参数时 MUST（必须）提升格式版本并只重建可派生缩略图，不修改原图或侧车。

格式版本清空缩略图树后，正常素材 MUST（必须）只从正常对象树重建，回收站素材 MUST（必须）只从回收站权威本体重建。位置 MUST（必须）由 Catalog 派生索引的删除状态显式决定，MUST NOT（禁止）通过先试正常路径、失败再试回收站的 fallback 猜测。

右侧检查器 MUST（必须）在单击图片时展示活动项，并将图片摘要、色卡、组织、备注、关联提示词和文件信息分为可折叠且可定位的纵向分区，MUST NOT（禁止）要求使用者在互斥 Tab 间切换才能了解单张图片。多选时检查器 MUST（必须）改为共同值、混合值与批量操作状态。

完整原图灯箱 MUST（必须）由双击或 `Enter` 显式进入，MUST NOT（禁止）成为单击的默认结果。灯箱 MUST（必须）支持按当前查询顺序浏览相邻图片、适合窗口、100% 比例、缩放与平移，并 MUST（必须）在 `Esc` 后恢复集合滚动位置与活动项。界面层 MUST NOT（禁止）读取图片像素完成这些操作。

#### Scenario: 瀑布流切换到详情列表

- **WHEN** 使用者在已选图片并应用文件夹与标签筛选时切换到详情列表
- **THEN** 列表保留原查询与选择，并以信息列呈现同一结果集

#### Scenario: 浏览详情列表

- **WHEN** 当前结果包含多张图片且使用者切换到详情列表
- **THEN** 列头与行数据稳定对齐，行之间使用轻量分隔，悬停与选中不改变行高或数据列位置

#### Scenario: 回收站瀑布流在临界高度保持稳定

- **WHEN** 回收站四张不同画幅图片的虚拟总高接近容器可见高度
- **THEN** 连续 120 帧中集合客户区、第一张卡片宽高和总滚动高度各只有一个值，横向溢出为 0

#### Scenario: 超长图不放大低分辨率缩略图

- **WHEN** `676 × 1726` 图片在中等密度瀑布流中以约 `223 × 569` CSS 像素呈现
- **THEN** 派生缩略图至少为 `401 × 1024` 源像素，浏览器不把 `201 × 512` 旧缩略图放大显示

#### Scenario: 缩略图换代后重建回收站图片

- **WHEN** 缩略图格式从 2 升到 3 且某张图片权威本体只存在回收站树
- **THEN** Catalog 把位置显式传给重建器，新缩略图从回收站本体生成，不返回 `library.thumbnail_failed`

#### Scenario: 单击图片只更新检查器

- **WHEN** 使用者在瀑布流中单击一张图片
- **THEN** 图片成为活动项且右检查器更新，瀑布流不被详情页替换

#### Scenario: 灯箱浏览相邻图片后返回

- **WHEN** 使用者从瀑布流打开灯箱、查看下一张图片并按 `Esc`
- **THEN** 应用回到原查询与滚动上下文，并把灯箱最后查看的图片设为活动项

### Requirement: 图片多选与批量组织

图片瀑布流与详情列表 MUST（必须）使用同一选择模型，并区分唯一活动项与多项选择集合。`Ctrl+单击`、`Shift+单击`、`Ctrl+A` 与瀑布流框选 MUST（必须）分别支持增减项、连续范围、当前查询全选与空间框选。多选时 MUST（必须）呈现选中数量与中央区底部上下文操作栏，右检查器 MUST（必须）只呈现共同值、混合值与批量操作。

批量操作 MUST（必须）至少覆盖移动到唯一图片文件夹、添加/移除标签、收藏/取消收藏、建立普通提示词关联与移入图片回收站。右键菜单 MAY（可以）提供同一操作的快捷入口，但关键批量操作 MUST（必须）同时存在可见入口。任一批量权威写入失败 MUST（必须）返回逐项结果或按已批准事务语义回滚，MUST NOT（禁止）以部分成功冒充全部成功。

#### Scenario: 跨视图保留图片多选

- **WHEN** 使用者在瀑布流选中十张图片后切换到详情列表
- **THEN** 十张图片仍处于选中集合，活动项与批量操作栏保持可识别

#### Scenario: 批量移动图片

- **WHEN** 使用者把十二张不同文件夹的选中图片移动到 `构图参考`
- **THEN** 成功项只归属于 `构图参考`，失败项以显示文件名和错误码呈现

#### Scenario: 批量添加图片标签

- **WHEN** 使用者对十二张选中图片执行添加标签 `构图参考`
- **THEN** 全部目标图片权威元数据与索引可查询到该标签，失败项以显示文件名和错误码呈现
