## Why

Vistash 已具备图片管理的功能性纵向切片，但当前界面仍是验证后端契约的简易实现，视觉层级、操作密度、导入导出闭环和模块边界不足以支撑长期使用。现在需要在图像反推界面继续暂停的前提下，把图片管理重构为完整、可扩展且具有独立品牌识别的 Windows 桌面工作区。

## What Changes

- 完整重构共享应用外壳与图片管理工作区，采用“高级媒体工作室”的图片优先视觉方向；提示词仍保留为一级入口，但本变更不重设计提示词工作区，也不增加图像反推、生图或 provider 配置入口。
- 启动后直接恢复上次工作现场；首次运行、库路径失效和库格式迁移使用独立的库生命周期界面。
- 图片中央区以可调密度的原画幅瀑布流为主视图，保留共享查询、排序和选择的详情列表；右侧使用纵向分区检查器，双击或 `Enter` 进入支持相邻导航、缩放和平移的沉浸式灯箱。
- 增加按钮、文件/文件夹拖放和剪贴板粘贴三类导入入口；文件夹导入保留相对层级并与同路径逻辑文件夹合并，大批量导入允许在单素材事务边界安全停止。
- 增加导出原图、复制图像和用 Windows 默认程序打开三类出站能力，并通过统一任务中心呈现进度、结果、取消与逐项失败。
- 增加可编辑的显示文件名，同时永久保留不可变的来源文件名；搜索匹配两者，导出默认使用显示文件名与真实扩展名。
- **BREAKING**：逻辑文件夹从一个素材可属于多个文件夹改为每个素材至多属于一个文件夹；标签继续承担多维分类，拖到文件夹的语义变为移动。
- **BREAKING**：升级库格式与素材侧车结构。零个或一个文件夹归属自动迁移，多归属素材必须由使用者选择唯一目标，迁移确认前不得修改原库，失败必须整体回滚。
- 引入深浅双主题与跟随系统选项，并建立 Vistash 轻量品牌基础、语义 design token 和可访问的内部 UI 模块。
- 前端重构为 `library-lifecycle`、`asset-library`、`prompt-library` 三个纵向深模块；导航、任务中心、全局搜索与平台 adapter 是少数应用级 seam，图片业务实现不再泄漏到 `App.tsx`。
- 保持 10,000 项轻量查询加真实 DOM 虚拟化的规模门禁；本变更不引入分页、智能文件夹、重复管理、EXIF 检索、相似搜索、图片编辑、通用素材撤销或原生拖出。

## Capabilities

### New Capabilities

- `asset-transfer`: 定义文件、目录和剪贴板导入，以及导出、复制图像、默认程序打开、安全停止与传输结果语义。
- `workspace-task-center`: 定义长任务的全局进度、取消、完成报告、逐项失败和界面反馈层级。

### Modified Capabilities

- `app-shell`: 修改启动恢复、欢迎与迁移界面、紧凑顶栏、主题、设置、全局搜索和模块化工作区外壳要求。
- `asset-library`: 修改文件夹单一归属、显示文件名、目录层级导入、素材集合、检查器、多选、灯箱、组织操作、迁移与性能要求。

## Impact

- 前端：重构 `app/src/App.tsx`、`app/src/features`、`app/src/shared/ipc.ts` 与全局样式；新增 Radix Primitives、TanStack Query、CSS Modules、语义 design token、任务中心和平台 adapter。
- Rust/Tauri：新增或修订剪贴板文件与位图读取、显示文件名、单归属文件夹、目录层级导入、任务取消、导出、复制图像和默认程序打开相关 command 与错误语义。
- 库格式：素材侧车与库格式版本发生不兼容变更，需要带冲突处理和整体回滚的显式迁移。
- 测试：用 Tauri 生产 adapter 与内存测试 adapter 验证深模块 interface；更新 React 行为测试、Rust 迁移与事务测试、Windows 剪贴板/外部打开验收和 10,000 项性能基线。
- 视觉：在生产实现前制作独立高保真原型，确认应用图标、字标、深浅主题、三栏布局、灯箱和关键任务状态后再写回最终设计。
