# 回收站还原与清空验收（9.5）

日期：2026-08-28。承接 9.4 尚未提交的成果完成 9.5，当前变更进度 62/75。本轮不提交、推送或切换默认 App。

## 实现范围

- 单选检查器、多选检查器与底部操作栏提供还原入口。目标在操作开始时固定，逐项调用现有 Rust 单素材还原事务，成功项退出回收站，失败项仍可选中重试。
- 删除前位置由权威侧车决定，界面不再把删除后的空 `folder` 字段误报为“原文件夹是未分类”。缺失原文件夹作为成功附带提示呈现，列出图片显示名、缺失路径、已还原到未分类和稳定提示码。
- 清空通过 AlertDialog 二次确认，明确针对整个图片回收站、包含当前筛选未显示的图片、无法还原且不删除库外源文件。空回收站禁止清空。
- 确认后先读取完整回收站快照，以哈希解析显示文件名，再调用现有 `purge_trash`。读取失败不提交删除，不以来源文件名静默替代显示名。
- 清空成功、部分失败或整体错误均刷新实际集合、计数与关联详情。删除后索引重建失败不冒充整体回滚，界面明确提示以刷新后的实际内容为准。
- 回收站报告按应用 QueryClient 生命周期与库身份隔离，直到使用者关闭才移除。切库后不继续发出旧库的后续还原或清空请求，返回原库仍能查看未处理报告；此处不提供伪造的用户停止按钮。
- 集合读取失败增加明确重试入口；清空确认关闭后焦点回到集合搜索，避免落在已经禁用的清空按钮上。

既有“移入回收站”继续表示可恢复删除。全部界面沿用 `frontend-design` 的 Archive Desk 和现有 UI 模块，没有新增依赖、Rust command 或库格式。10.3 只补齐内部任务协调和就地异常反馈，不增加全局任务中心。

## TDD 与回归

通过 `asset-library/index.ts` 的公开界面验证，模拟只发生在 Tauri IPC 系统接缝。新增 6 项行为测试，图片模块共 68 项：

1. 单张还原恢复原文件夹，图片离开回收站后报告保留。
2. 多选还原把原文件夹缺失的成功与事务失败分开，失败图片可重试。
3. 清空确认覆盖全部图片，取消不写入，筛选外失败图片使用显示文件名。
4. 清空前读取失败不执行永久删除，查询可明确重试。
5. 切库后不继续还原旧库目标，返回原库可查看未处理报告。
6. 清空在部分删除后报错仍刷新真实剩余图片，不声称全部未删除。

红—绿循环捕获了缺失入口、缺失原文件夹展示、清空前读取失败缺少重试，以及切库丢失报告的问题。旧左栏测试把布局恢复误当成文件夹查询完成，现分别等待实际可观察状态，不改测试池、超时或门禁配置。

## 浏览器验收

`app/scripts/trash-check.py` 使用 `webapp-testing` 的 Python Playwright 与 Windows headless Edge，覆盖深/浅主题、1440×900/760×600。通过真实界面执行移动到文件夹、删除图片、删除原文件夹、部分还原失败、再次还原到未分类、筛选下清空确认/取消、部分清空失败及再次确认清空。

故障注入和永久删除仅作用于开发展台内存数据，不打开或修改真实素材库。截图与报告保存在 `app/artifacts/trash/`，已查看深色宽屏还原结果与浅色窄屏永久清空确认。
