# 显示文件名编辑验收（9.2）

日期：2026-08-28。承接现有未提交开发成果，完成任务 9.2；当前进度为 59/75。

## 实现范围

- F2、工具栏“修改文件名”和检查器“编辑显示文件名”共用一个编辑 Dialog。打开时冻结素材身份和名称信息，只提交 `rename_asset_display_filename(hash, stem)`。
- 输入框仅编辑名称主体；真实扩展名单独只读显示。检查器保留显示名、来源名和真实扩展名，不编辑来源记录或图片本体。
- 正常单选才允许编辑；多选、回收站、非活动工作区、查询占位数据及其他输入框/弹层不响应 F2。
- 保存失败保留输入和错误码。名称非法时标记输入无效并聚焦该字段；元数据写入失败不把合法名称标为无效。
- 每次打开创建独立表单会话，取消后重新按 F2 不继承上次错误。不存在自动保存、自动重试或把旧输入套用到另一张图片的逻辑。
- 成功后仅失效本库集合与目标详情。名称变化导致图片退出当前搜索时保留搜索词，关闭后焦点回到搜索框；仍能按不可变来源名和新显示名找到同一图片。
- 窄窗口通过“图片信息”进入文件身份区，并支持在该层内打开和关闭名称编辑。完整检查器的其余分区属于 9.3。

沿用 Archive Desk 视觉、现有 UI 模块与平台接口，没有新增依赖、原生命令或库格式。通用 Dialog 只新增可选的打开/关闭焦点回调，原有调用行为保持不变。

## 红—绿回归

测试从 `asset-library/index.ts` 公开 interface 渲染，只在 Tauri 传输接缝模拟后端，不访问内部 implementation。

1. F2 首次回归因缺少入口失败，接入后可选中完整名称主体并保存。
2. 失败后关闭、重新按 F2 的回归捕获了旧错误残留；把错误和草稿收进每次打开的独立表单后转绿。
3. 只读元数据错误曾错误设置 `aria-invalid=true`；现在只有 `library.filename_invalid` 会标记字段无效。
4. 真实浏览器捕获非法名称拒绝后焦点未回到输入框；增加提交结果后的字段聚焦后转绿。
