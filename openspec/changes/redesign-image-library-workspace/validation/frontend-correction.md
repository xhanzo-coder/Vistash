真实 Tauri 复查发现“标题显示 5 张图片但集合空白”：旧实现把所有筛选共用 `assets-collection` 滚动键，长列表的 520px 偏移污染了短文件夹查询。公开回归先稳定复现 `scrollTop` 仍为 520；现按文本、标签、文件夹、收藏与位置生成独立滚动键，显式迁移旧键，并把超出内容高度的历史偏移限制到有效范围。原实机现场复查后 5 张图片正常显示。

10,000 项性能首次复验时，图片瀑布流/详情列表均达标，但提示词列表→卡片稳定为 70—84ms。分段测量确认按钮 dispatch 仅 5ms，68ms 等待发生在卡片 DOM：提示词瀑布流每次以宽度 0 挂载，等待 `useEffect` 注册的 ResizeObserver 后才建立虚拟项。改为 layout effect 中同步取得首次宽度、后续仍由 ResizeObserver 更新；不常驻两套视图、不增加隐藏媒体租约。最终结果：图片首屏 115ms、初始/峰值 DOM 18/32、最坏双帧 13.4ms、切换 25ms；图片详情列表 11/14 DOM、最坏 15.2ms、切换 25ms；提示词列表→卡片 20ms。所有既定阈值保持不变。

用户随后截图报告折叠导航仍出现竖排“文件夹/标签”和横向滚动。新 Edge 页面同源码无法复现，而长期运行的 Tauri 终端记录到删除 export 后 HMR 失败、Fast Refresh invalidation 与 Hook dependency 数量变化；差分确认是多轮结构编辑后的旧模块/CSS 状态。干净重启真实 Tauri 后，56px 图标栏只保留展开、全部、收藏、未分类和回收站，分区隐藏且无横向滚动。`panel-and-list-check.py` 新增折叠分区 `to_be_hidden`、`scrollWidth <= clientWidth` 与深浅截图，正式构建状态被永久锁定。
