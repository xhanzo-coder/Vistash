## Context

提示词工作区已经具备查询、文件夹、共享标签、收藏、回收站、卡片瀑布流、详情列表、统一选择、批量组织、正文显式编辑、备注自动保存、图片关联与封面等完整行为，并有覆盖公开工作区的 React 测试。问题不在后端能力，而在生产呈现仍来自重构前的 `PromptWorkspace.tsx` 与 `styles.css`：装饰性 eyebrow、横向堆叠表单、文字按钮、虚线空状态和旧栏位使其与 Archive Desk 图片工作区完全割裂。

本变更发生在 `redesign-image-library-workspace` 完成主要图片纠偏之后。图片模块已经冻结可复用的 design token、UI primitives、三栏断点、栏位 separator、单行查询栏、图标/短文案分层和浏览器验收方法。提示词重构必须复用这套系统，但不能抽象成图片/提示词共用的 `GenericWorkspace<T>`，因为两类素材的卡片、编辑与关联知识不同。

## Goals / Non-Goals

**Goals:**

- 让图片与提示词两个一级入口表现为同一个 Vistash 产品，同时保留各自领域身份。
- 以提示词正文可读性和快速复用为中心，完成左导航、中央集合、右检查器、聚焦编辑和批量操作的生产级呈现。
- 保留现有权威写入、草稿拦截、错误语义、查询、选择、关联、回收站和滚动恢复行为。
- 把提示词生产样式从旧全局 `styles.css` 迁移到模块级 CSS，并保持唯一公开模块出口。
- 继续满足 10,000 项虚拟化、深浅主题、720px 最小窗口、键盘和减少动态效果门禁。

**Non-Goals:**

- 不实现图像反推、生图、provider/API Key、模型调用或反推结果界面。
- 不修改提示词数据格式、SQLite、关联语义或文件夹多归属规则；只增加提示词文件夹子树移动所需的 Rust/Tauri command。
- 不增加提示词版本历史、负向提示词、第二份主正文、评分、智能文件夹或富文本/Markdown 渲染。
- 不把提示词与图片组件抽象成泛型目录，不重做共享应用顶栏或图片工作区。
- 不引入新的组件库、图标库、状态库或路由。

## Decisions

### 1. 同一 Archive Desk 系统，不是图片页面换文案

提示词使用与图片工作区相同的 Graphite/Bone/Signal Coral token、Bahnschrift/Microsoft YaHei UI 与 Georgia/SimSun 字体、Phosphor regular 图标、1px 分隔和 Workbench 三栏节奏。页面不复制图片卡片：纯文本提示词以正文排版为视觉主体，有封面时图片只作为引用上下文。

备选是只替换旧 CSS 颜色和圆角。它不会修复按钮堆叠、空状态、上下文重复和模块样式所有权，因此拒绝。

### 2. 保持 `prompt-library/index.ts` 公开 interface，内部按知识簇拆分

`PromptWorkspace` 的公开 props 与应用导航 seam 保持不变。内部逐步拆为 session/query、navigator、collection、inspector、editor、organization、association 和 trash/batch 等知识簇；测试继续从公共出口观察。现有 `features/prompts` 中确属提示词领域的卡片、详情列表、封面和编辑组件迁入模块 `internal/`，共享选择/布局算法只在已有真实复用时留在 `features/workspace`。

备选是一次性重写数据流。现有行为测试已经证明业务协调可用，重写会把视觉问题扩大为数据风险，因此拒绝。

### 3. 操作显隐按频率与选择上下文分层

中央查询栏只保留搜索、排序、密度与视图。单选操作集中在检查器摘要：复制正文、编辑、收藏、关联图片与移入回收站；多选底栏直接显示文件夹、标签和一个收藏状态，关联与回收站进入“更多”。检查器多选只汇总，不复制动作。永久清空仍使用阻断确认，普通移入回收站沿用可还原语义。

备选是保留全部文字按钮以提高可发现性。图片实机反馈已经证明它会形成重复和噪声；图标按钮通过 Tooltip、`aria-label` 和键盘状态补足可发现性。

### 4. 左右栏与响应式复用图片栏位协议

提示词继续独立保存 `railWidth`、`inspectorWidth`、`railCollapsed`、`inspectorCollapsed`，但呈现与图片统一为可聚焦 separator：拖动结束才持久化，方向键 8px，Home/End 边界，双击复位。宽屏保持三栏；≤1050px 左栏成为图标/覆盖导航；≤780px 检查器成为覆盖 Dialog。响应式状态不写回宽屏偏好。

拒绝用 JS 监听宽度后写死 display 状态；断点由 CSS/`useSyncExternalStore` 只决定实际呈现，偏好保持领域数据。

### 5. 卡片与列表共享查询/选择，但各自拥有信息密度

卡片瀑布流继续由 TanStack Virtual lanes 实现，纯文本卡片使用标题、正文摘要、模型/平台、标签和关联数建立层级；有封面时只展示一张真实关联图片与 `+N`。卡片附属动作不嵌套按钮，悬停、焦点和选中时增强。

详情列表列固定为标题/正文摘要、文件夹、标签、关联图片数、模型/平台、收藏与更新时间；使用容器查询按优先级隐藏列。两种视图共享 Selection Provider、活动项、查询与独立滚动键，不同时常驻两套媒体 DOM。

### 6. 检查器是连续文档，聚焦编辑器只服务长正文

单选检查器使用摘要、正文、组织、备注、关联图片五个连续可折叠分区，不增加顶部重复定位标签。摘要承载上下文动作；正文默认可读，显式编辑进入现有聚焦编辑器。组织和备注保持原保存语义，关联图片区保留库内选择、本地导入、封面和删除态。

多选检查器只显示共同/混合文件夹、标签、收藏、模型和关联数；正文与备注不出现。空检查器使用一句选择提示，不用 `INSPECTOR` eyebrow。

### 7. CSS Modules 切换，不保留双视觉系统

新提示词工作区使用模块级 CSS，消费现有语义 token。实施完成后删除 `styles.css` 中只属于提示词旧工作区的规则；仍被未迁移共享/历史组件消费的规则必须先通过引用检查确定所有权。正式入口不保留旧样式开关。

### 8. 性能与验证

沿用 10,000 项门禁：初始集合 DOM ≤24、快速滚动峰值 ≤40、平均双帧 ≤20ms、最坏 ≤35ms、稳定 heap ≤60MiB、切换后 ≤65MiB、视图切换 ≤50ms。提示词卡片从列表切回时必须在 layout effect 中同步取得首次容器宽度，不等待多轮 ResizeObserver 才出现首项。

验证分为公共 React 行为、开发内存展台的 1440/1274/960/760 深浅截图、键盘/焦点/无水平溢出、10,000 项性能和真实 Tauri 用户验收。测试照片只使用明确 fixture；不把假图或测试控制带入生产。

### 9. 浏览范围用导航选中态表达，不再重复成条件胶囊

“全部提示词、收藏、提示词根位置、具体文件夹、回收站”与图片侧一样是互斥浏览范围：点击任一入口原子更新 `folder/favorite/location`，同时清理文本和标签；不会再出现收藏与提示词根位置同时高亮。搜索框本身、左栏标签按下态和范围入口已经完整表达当前条件，因此删除中央区的 `AppliedFilterChips` 行，不再重复显示“只看收藏”“文件夹：…”等胶囊。

备选是只隐藏收藏胶囊而保留其他胶囊。它仍会让同一状态在搜索框、左栏和中央区出现两次，并留下额外垂直跳动，因此拒绝。

### 10. 提示词文件夹复用图片侧交互协议，保留提示词多归属语义

提示词文件夹树采用与图片侧相同的视觉和操作词汇：标题旁只留“新建文件夹”；新建在树内即时输入；具体节点右键提供新建子文件夹、重命名、移到顶层、移动文件夹和删除；指针拖动文件夹节点到另一节点或树根位置；移动 Dialog 作为键盘等价入口。拖动载荷只含逻辑路径，不复用提示词卡片选择载荷。

核心新增 `move_prompt_folder(source, destination_parent)`：事务化重映射完整子树、文件夹清单以及所有提示词的每一条受影响成员关系，其他文件夹归属保持不变。自身、后代、缺失父级和目标碰撞显式拒绝。它与重命名共用同一个子树重定位实现，不把提示词改成图片的单文件夹归属。

### 11. 手动新增提示词使用聚焦创作面板

中央标题区提供唯一主动作“新建提示词”，空库/空文件夹状态复用同一入口。打开后进入聚焦创作面板而不是在侧栏塞小表单：正文占主要面积并且唯一必填，标题、模型/平台和参数为可选辅助字段。当前具体文件夹自动成为初始归属；其他范围从根位置创建。组织标签和图片关联留到创建后的检查器，避免首次写入表单过载。

`Ctrl+S` 与主按钮共用创建写入；保存成功后清除会隐藏新条目的搜索、标签、收藏和回收站条件，切到目标文件夹或提示词根位置，刷新权威快照并聚焦新条目。创建器挂载时冻结初始归属并注册现有 `setPromptDraftGuard`；取消、一级导航、切库与关闭窗口都复用同一三选一确认，外部导航不能修改保存目标。备选是右检查器内永久放一套创建表单，它会压缩浏览空间、和单选检查器争夺身份，因此拒绝。

### 13. Code review 后的模块深化

提示词公开测试只从 `prompt-library/index.ts` 的 `PromptLibraryWorkspace` interface 进入，内部实现可自由拆分。`PromptWorkspace` 只保留 session/query/selection 组合；导航与文件夹组织下沉为内部 `PromptNavigator` 深模块，新建创作由 `PromptCreateFocus` 拥有草稿状态与全局守卫。

图片与提示词共享无业务状态的 `FolderTree`、`InlineFolderCreatorForm`、`FolderMoveTargetForm` 和路径计算工具；节点文案、上下文菜单、创建提交、导航和领域 mutation 仍由各自模块通过窄 props 拥有。拖放目标从 `string | null | undefined` 改为 `FolderDropTarget` 判别联合，消除顶层/非法状态的隐含约定。文件夹叶节点名称统一由已验证的路径工具计算，不在调用处重复 fallback。拒绝抽成 `GenericWorkspace<T>` 或共享领域 mutation。

### 12. 图片与提示词共享显式顶层拖放提示

共享 `useFolderTreeDrag` 已能把带 `data-folder-tree-root` 的命中解释为 `destinationParent=null`，但静态空白命中面积不足。两棵树在 `preview !== null` 时各自渲染同构的首行“移到顶层”放置区，并把该行标记为根目标；共享 hook 继续只负责几何裁决，不拥有领域文案或命令。命中高亮由各模块 CSS 消费同一 `data-drop-active` 状态。

该放置区不常驻，避免把低频操作变成永久导航项；拖动开始后才揭示，右键和移动 Dialog 继续承担无指针设备与键盘入口。

## Risks / Trade-offs

- [Risk] 旧 `PromptWorkspace` 行为密集，视觉拆分可能破坏草稿拦截或焦点恢复 → 以公共测试逐条迁移，每个纵向切片先红后绿，不重写权威协调。
- [Risk] 删除全局 CSS 误伤图片或生命周期页面 → 通过类名引用清单和浏览器矩阵逐项迁移，最后才删除零引用规则。
- [Risk] 卡片正文更可读会增加高度估算误差 → 使用确定的行数/排版 token 与现有估算 seam，复测 10,000 项滚动和框选。
- [Risk] 有封面卡片再次变成“图片库卡片” → 封面面积受限，标题/正文始终保留，图片只表达关联上下文。
- [Risk] 两个工作区控件看似相同却行为不一致 → 复用现有 UI primitives 和栏位交互协议，不复制业务状态实现。
- [Trade-off] 不在本轮统一提示词与图片的所有内部算法 → 保持深模块，等真实第三个消费者出现后再评估共享 seam。

## Migration Plan

1. 固定当前功能与视觉失败基线，补充提示词公开界面显隐、栏位和列表列测试。
2. 建立提示词模块 CSS 与工作台骨架，先迁移导航/查询/空状态，不改变数据流。
3. 迁移卡片瀑布流与详情列表，完成选择、滚动、性能和媒体租约回归。
4. 迁移单选/多选检查器、聚焦编辑、组织、备注、关联、回收站和批量栏。
5. 接入独立栏位偏好与窄窗口覆盖，完成深浅/宽窄/键盘浏览器验收。
6. 删除零引用旧提示词样式，运行完整前端/Rust门禁、性能、Web Guidelines 和代码审查。
7. 在真实 Tauri 中由用户确认图片与提示词属于同一设计系统后归档。

若中途失败，生产入口保持在最后一个通过公共测试的纵向切片；不引入运行时 legacy 开关。此变更不涉及数据迁移或后端回滚。

## Open Questions

无阻断实施的问题。设计方向沿用用户已经确认的 Archive Desk A；具体卡片正文行数、列隐藏阈值和栏宽范围由首个生产切片在 1440/1274/960/760 fixture 上测量后写入验证记录。
