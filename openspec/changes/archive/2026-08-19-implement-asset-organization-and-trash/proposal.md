## Why

Vistash 已能可靠导入并浏览百张素材，但素材数量一增长就只能靠文件名滚动查找，现有文件夹、标签和回收站字段仍没有可操作的产品能力。下一步必须补齐 v1 素材管理下限，使素材在进入反推阶段前已经可以被组织、检索和安全管理。

## What Changes

- 实现逻辑文件夹：创建、重命名、删除，支持一个素材属于多个文件夹，空文件夹继续独立持久化。
- 实现标签：为素材添加或移除标签，提供库内标签清单，并把变更写回素材侧车。
- 实现素材查询：按文件名文本与所选标签组合过滤正常素材；查询结果不混入回收站内容。
- 实现库内回收站完整链路：删除、列表、还原、原文件夹缺失提示，以及二次确认后的永久清空。
- 实现素材工作区界面：文件夹与回收站侧栏、搜索与标签筛选区、素材网格、详情操作与明确的空状态/失败状态。
- 为文件夹级批量元数据更新、删除/还原回滚、索引重建等价性、搜索组合语义和界面关键流程建立测试。
- **BREAKING** 无。库格式版本保持不变；本变更实现的字段和目录已经存在于当前公开库格式中。

不在本次范围：

- 不实现智能文件夹、批量重命名、去重面板、文件系统监控或 PSD/RAW 专用预览；这些仍受现有 v1 范围需求排除。
- 不实现提示词库与图像反推；本变更只完成它们依赖的素材组织地基。
- 不引入多级撤销历史；删除的恢复入口是库内回收站，普通标签和文件夹编辑失败则显式报错并保持原数据。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `asset-library`：补充文件夹层级与成员关系、标签规范、组合查询、文件夹变更语义，以及删除/还原/清空的可测试操作契约。

## Impact

- Rust 核心层新增素材组织与回收站编排，扩展 `library`、`sidecar` 与 `index` 的公开接口，但继续保持核心 crate 不依赖 Tauri。
- SQLite 索引增加面向查询和标签清单的读取接口；索引仍是可删除重建的派生数据，不引入不可重建字段。
- Tauri command 与 `src/shared` IPC 增加文件夹、标签、查询、删除、还原和清空操作。
- React 素材视图从线性列表升级为工作区布局，并增加对应组件测试与 Windows 交互验收。
- 不新增模型供应商、网络服务或运行时凭据，不改变库格式版本。
