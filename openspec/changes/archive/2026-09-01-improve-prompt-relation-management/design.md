## Context

当前图片检查器与提示词检查器都已经通过 `unlink_image` 和共享关系协调器完成可靠解除，但唯一入口藏在逐项 `···` 菜单。功能存在、错误语义和双向刷新也正确，问题是操作不可发现。提示词卡片已经使用 `resolved_cover_hash` 只租用一张封面，但数量使用“剩余 `+N`”语义，使用者必须心算总数，并容易误以为应该用四宫格表达多图。

本变更只调整关系操作的呈现与卡片信息层级，不改变关系模型、IPC、查询、封面持久化或图片字节。

## Goals / Non-Goals

**Goals:**

- 两侧检查器中的每个关联对象都能直接找到解除关联操作，同时保留 `···` 菜单等价入口。
- 打开对方、切换预览和解除关联保持独立命中区，避免误触。
- 提示词卡片始终只展示一张代表封面，并在多图时直接显示关联总数。
- 不为卡片额外申请三张缩略图，不增加网络/IPC 瀑布或大列表租约压力。
- 保持键盘、触屏/窄窗口、深浅主题和 busy/error 状态一致。

**Non-Goals:**

- 不引入四宫格、轮播或卡片内图片浏览。
- 不增加解除确认 Dialog；解除不会删除素材，重新关联即可恢复关系。
- 不实现通用撤销栈或跨页面 Toast undo。
- 不修改显式封面设置、默认封面解析和详情画廊顺序。

## Decisions

### 1. 直接动作与菜单双入口

每个图片侧提示词关系行、提示词侧图片缩略图都增加独立的 broken-link 图标按钮，使用明确的可访问名称“解除与……的关联”。宽屏指针设备在行/缩略图悬停、`focus-within` 或选中时显示；不支持 hover 的设备及窄窗口始终显示。`···` 菜单继续保留“解除关联”，两者调用同一 mutation。

直接按钮不能覆盖主体按钮：图片侧主体仍打开提示词，提示词侧缩略图主体仍只切换主预览。直接解除按钮位于右上/右侧动作槽，使用现有 destructive 色、原生悬停提示和完整可访问名称，不使用含义模糊的裸 `×`，也不要求组件额外挂载 Tooltip context。

备选方案是只在分区标题放一个“管理”按钮，但它仍要求进入第二层选择，不能解释具体将解除哪一项；因此拒绝。

### 2. 无确认框，保留权威失败语义

解除关联不删除、移动或改写图片/提示词，所以不弹删除确认框。点击后立即进入 busy，禁用该关系的重复解除与菜单动作；成功由现有关系 revision 刷新双方，失败继续显示稳定错误。被解除项从当前集合消失就是主要成功反馈。

### 3. 卡片使用单封面与总数标记

卡片封面来源不变：显式封面优先，否则 `resolved_cover_hash` 已给出第一张有效关联图片。关联数大于一时在封面角落显示总数 `N 张`；一张时不显示数量标记，无图时保持正文主导卡片。总数比 `+N` 无需心算，也与详情列表“关联图片数”一致。

四宫格被拒绝：它会让每张图片在当前卡片宽度下过小、增加三个缩略图租约、放大瀑布流视觉噪声，并错误地把提示词卡片变成相册。全部图片只在检查器的主预览＋缩略图画廊展开。

### 4. React 与大列表边界

计数直接从现有 `linked_image_hashes.length` 派生，不新增 effect、query 或组件状态；卡片仍只挂载一个 `PromptCoverImage`。直接解除按钮复用现有 mutation，不建立第二套关系状态。事件处理只位于按钮自身，避免在父卡片增加传播分支。

## Risks / Trade-offs

- [Risk] 直接 destructive 图标增加视觉密度 → 仅在 hover/focus/selected 上下文出现，窄窗口保持紧凑动作槽。
- [Risk] 图标含义不明确 → 使用 broken-link 图标、原生悬停提示和完整可访问名称，不使用裸关闭符号。
- [Risk] 菜单与直接入口行为漂移 → 两者调用同一解除函数并由同一测试 seam 观察 `unlink_image`。
- [Risk] 总数标记遮挡封面主体 → 固定在安全角落、使用紧凑表面和短文本，只在 `>1` 时显示。

## Migration Plan

1. 先以公开组件/工作区测试锁定当前缺少直接入口和 `+N` 计数。
2. 增加直接解除按钮及响应式显隐样式，复用既有关系 mutation。
3. 把卡片计数改为总数 `N 张`，保持单一封面租约。
4. 运行相关测试、完整前端/Rust 门禁、视觉矩阵和双轴审查。

无需数据迁移；回滚只恢复 UI 呈现，不影响已有关系或封面。

## Open Questions

无。用户已经确认单封面＋总数、详情全缩略图和直接解除入口。
