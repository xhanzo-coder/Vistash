## Context

普通关联的权威数据、双向刷新、回收站定位和封面回落已经由 `image-prompt-relations`、现有 IPC 与提示词侧车实现。当前问题集中在前端编排：单图关联入口由 `AssetPromptLinks` 自管，图片多选又走只能选择一条提示词的 `BatchEditDialog`；提示词侧的 `PromptImageLinks` 把每张缩略图主体直接作为跨页打开按钮，无法在提示词上下文中先比较多张图片。

本变更必须保持现有 Archive Desk 三栏系统、公共模块出口和普通关联语义。用户已经确认 v0.1.0 不实现反推、自动生成、自动匹配或来源关系；图片页面创建提示词只是一份使用者手写素材与普通关联的组合操作。

## Goals / Non-Goals

**Goals:**

- 单图与多图使用同一图片上下文关联台，并在提交前准确显示目标图片、提示词与新增关系数量。
- 允许从图片上下文手动创建提示词并立即关联，保留创建成功后的权威提示词，即使关系写入失败。
- 让提示词关联多图时能在原地切换大图预览，再通过显式动作打开图片工作区。
- 保留既有刷新屏障、回收站可见性、封面、从本地导入、错误码、键盘和响应式语义。

**Non-Goals:**

- 不调用视觉模型、不读取像素生成文本、不预填提示词正文、不提供匹配分数。
- 不新增关系类型、SQLite 表、侧车字段、Tauri command 或依赖。
- 不把图片与提示词工作区抽象成泛型页面，也不重做应用壳层、文件夹或查询模型。
- 不增加关联顺序拖动；封面继续由现有显式值与确定性回落规则决定。

## Decisions

### 1. 单图与多图共用冻结目标的关联 Dialog

新增图片模块内部 `PromptAssociationDialog`，接收打开时冻结的 `AssetRow[]`。单图从检查器打开，多图从底部“更多”打开；Dialog 左侧呈现当前图片上下文，右侧搜索和多选正常提示词。选择、筛选或集合刷新不得改变本次目标。

候选使用 `PromptRow.linked_image_hashes` 计算每条提示词相对冻结图片的缺失关系数：全部已关联的候选保留并禁用，部分已关联的候选仍可选择；底部显示所有已选候选的缺失关系数总和，而不是简单用图片数乘提示词数冒充新增数量。

备选是继续保留单图与批量两套 Dialog。它会维持“一边可多选提示词、另一边只能单选”的不一致，并复制搜索、错误和刷新状态，因此拒绝。

### 2. 关系提交继续经过 `ImagePromptRelations`

关联台把全部目标图片与全部目标提示词作为一次 `link` command 交给 `ImagePromptRelations.execute`。同一提示词的一组图片由现有 `link_images` 权威事务处理；协调 Module 按提示词报告失败并在成功后等待图片详情、提示词快照、封面与候选刷新。

备选是扩展旧 `batch_link_to_prompt` 前端编排并在 UI 自行失效缓存。它会重新制造两套关系写入与刷新路径，正是前一变更已经消除的问题，因此拒绝。

### 3. “新建并关联”是两步显式组合，不伪造原子事务

关联 Dialog 内提供“选择已有”和“新建提示词”两种模式。新建表单正文必填，标题、模型/平台和参数可选；文件夹与标签为空，使新提示词进入提示词根位置。表单不接收图片分析结果，也不自动填充任何字段。

提交先调用现有 `create_prompt`，成功后再通过 `ImagePromptRelations.execute` 建立普通关联。创建失败时保留草稿；创建成功但关联失败时保留新提示词并展示稳定失败码与“提示词已创建、关联失败”，重试只重试关联。成功后关闭 Dialog，停留在图片工作区。

备选是在第二步失败时删除新提示词以模拟原子性。删除会破坏已经成功的权威写入，也可能再次失败，因此拒绝。

### 4. 图片上下文表单拥有独立草稿守卫

新建模式在草稿非空时注册现有全局提示词草稿守卫；关闭 Dialog、切换一级工作区、切库或关闭窗口都进入同一“保存并继续 / 放弃草稿 / 留在当前页面”决议。Dialog 关闭后立即注销守卫，不能影响提示词工作区自己的编辑器。

备选是只拦截 Dialog 的取消按钮。它无法覆盖顶栏导航和原生窗口关闭，会造成手写正文丢失，因此拒绝。

### 5. 提示词关联图片使用主预览与缩略图选择两层

`PromptImageLinks` 继续在提示词检查器的关联图片分区内读取 `linked_image_states`，但把呈现改为：一张当前主预览、当前图片身份与尺寸、缩略图选择网格和显式“打开当前图片”。初始主预览优先使用有效封面，否则使用第一张关联图片；单击缩略图只改变本地预览选择，不写权威数据、不跨页。

封面和删除态仍显示在对应缩略图及主预览上。每张缩略图的次级菜单保留设为/取消封面和解除关联；打开当前图片经过关系 Module 解析正常区或回收站。关联刷新后若当前选择消失，渲染阶段直接回落到有效封面或第一张，避免用 effect 复制派生状态。

备选一是只放横向轮播，它隐藏总数量和相邻图片；备选二是只放小网格，它无法检查单张图。主预览加缩略图同时保留比较与检查能力，因此采用。

### 6. 复用现有视觉系统，不引入新的页面形态

关联台使用现有 `Dialog`、`SearchField`、`Button`、语义 token、Phosphor 图标和缩略图租约；宽屏为图片上下文与提示词候选两列，窄屏上下排列。提示词图片主预览沿用 Archive Desk 的扁平 1px 分隔、暖珊瑚选中边和 Graphite/Bone 表面，不增加卡片套卡片或装饰动画。

## Risks / Trade-offs

- [Risk] 10,000 条提示词候选同时渲染会让 Dialog 变慢 → 沿用按文本查询和有限视窗；候选行保持紧凑，并以公共工作区性能 fixture 检查打开与输入响应。
- [Risk] 单图详情同时读取关联提示词、关联 Dialog 又读取候选产生重复请求 → 两者使用相同 TanStack Query key，由 QueryClient 去重并在关系 revision 后统一失效。
- [Risk] 新建成功但刷新失败会让用户误以为提示词未创建 → 明确区分“创建失败”“关系写入失败”“关系已写入但刷新失败”，不自动回滚。
- [Risk] 大图预览和缩略图重复申请媒体 URL → 继续使用现有缩略图租约与懒加载，不读取原图，也不让两套媒体 DOM 常驻在隐藏视图。
- [Trade-off] 图片多选关系失败按提示词事务组报告，而不是为每个笛卡尔积关系生成独立错误行 → 保留现有 `ImagePromptRelations` 窄接口和事务语义，界面用提示词标题与目标图片数解释失败范围。

## Migration Plan

1. 先以图片和提示词公共工作区测试锁定关联台、多选计数、新建并关联和图片预览行为。
2. 新增关联 Dialog 并先接替单图入口，再接替批量提示词关联；标签批量编辑保持原组件与命令。
3. 接入新建并关联及草稿守卫，验证创建成功/失败、关联失败和刷新失败。
4. 重做 `PromptImageLinks` 呈现，保留原导入、封面、删除态和解除回归。
5. 完成 1440/960/760 深浅主题、键盘、焦点和无水平溢出检查，串行运行全部门禁。

回滚只需恢复前端入口与呈现；权威库格式和普通关联数据没有迁移，不需要数据回滚。

## Open Questions

无阻断问题。关联图片缩略图列数由现有检查器宽度和 CSS 自适应决定，不写入布局偏好。
