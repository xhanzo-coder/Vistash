## 背景与原因

Vistash 已经建立开发工作流，但产品边界至今没有经过审批：`AGENTS.md` 把项目描述为"个人使用的 Eagle 替代品"，而仓库里唯一的正式调研产物《Viko 图片反推提示词技术深度调研与复刻蓝图.md》整篇讨论的是图像到生成控制语言的编译系统。两者互不引用，导致仓库同时存在两个彼此不知道对方存在的产品定义，也无法判断某个功能是否属于本项目范围。

归档变更 `bootstrap-vistash-development-workflow` 的待确定问题明确要求："第一个产品变更需要通过专项架构提案，决定初始运行时是否正式采用 Tauri 2、React/TypeScript、Rust 和 SQLite。"本变更就是该提案，同时把一次结构化设计审问中确定的产品边界与关键契约固化为可校验的规格，使后续每个能力变更都有稳定前提。

现在必须完成这件事，原因是构建顺序已经确定为"先定契约，再跑最窄纵向切片，最后建评测集"，而契约未定就无法开始任何实施；同时反推链路的数据形状取决于模型供应商对 JSON Schema 子集的支持程度，若不先固定契约骨架与待确定问题，调研结论将没有落点。

## 变更内容

- 确立产品边界：Vistash 是本地优先的图片素材管理器，叠加图像反推提示词能力；明确排除网页素材抓取。
- 正式采用 Tauri 2、React/TypeScript、Rust 与 SQLite 作为初始运行时，解除归档变更遗留的待确定问题。
- 规定媒体处理职责归属：图像解码、缩放、缩略图与色卡计算均在 Rust 侧完成，界面层不承担像素处理。
- 规定凭据所有权：应用不内置任何模型供应商密钥，由使用者自行提供；视觉理解层实现为可替换的 provider 接口。
- 确立素材库契约：素材文件复制进库，库格式为项目自有的开放格式，采用内容哈希寻址、可读元数据文件，且 SQLite 索引可从元数据完全重建。
- 界定 v1 管理范围下限：导入、缩略图网格、文件夹、标签、按标签与文件名搜索、单图预览，外加提示词库。
- 确立反推契约：两阶段视觉理解（先判定图像类型，再使用该类型专用 schema 观察）、内部结构化 JSON 与对外自然语言双层输出、按目标生图模型版本化的 `target_profile`。
- 确立色卡契约：由确定性像素算法独立产出，禁止视觉模型输出 HEX，并要求显式状态字段与算法版本标识；计算失败时颜色列表为空并携带显式错误码。
- 确立提示词记录契约：单一 append-only 记录表，区分反推产出、手写录入与编辑衍生，重跑反推追加新记录而不覆盖既有记录。
- 确立反推任务契约：显式状态机与幂等键，即使 v1 仅暴露单张按需入口也不省略任务层。
- 确立反推质量门槛：以 80 张固定冒烟集与"直接生成提示词"基线对比作为 v1 验收判据。
- 定义删除语义：库内删除移入库内自有回收站而非操作系统回收站，回收站内素材仍参与去重但独立报告，源文件被删除后库内副本为唯一权威副本。
- 定义导入域、回收站域与色卡域的错误码，明确回滚单元为单个素材、写入顺序为先本体后侧车。
- **范围收缩**：执行期间使用者确认首要目标是先交付替代 Eagle 的桌面框架，因此反推侧的字段级契约（观察 schema 骨架、编译提示词骨架、提示词记录表与反推任务表字段、视觉模型供应商选型）整体移交后继变更，见 `design.md` 第十八条与 `tasks.md` 文末清单。四份能力规格的需求级约束不在收缩范围内，随本变更归档生效并约束后继变更。
- **BREAKING** 无。本变更不修改任何既有运行时行为，因为仓库尚无生产代码。

## 能力范围

### 新增能力

- `product-architecture`：定义产品边界、初始运行时技术栈、媒体处理与界面渲染的职责分离、显式失败语义以及模型凭据所有权。
- `asset-library`：定义素材入库方式、库格式与索引可重建性、导入错误语义，以及 v1 素材管理范围下限。
- `reverse-prompt`：定义两阶段视觉理解、图像类型路由、观察结果结构、提示词编译与 `target_profile`、色卡产出契约、反推任务状态机、错误语义与质量门槛。
- `prompt-library`：定义提示词记录的 append-only 语义、来源区分、模型版本溯源与收藏行为。

### 修改能力

无。`development-workflow` 的现有需求不变；本次在阶段 B 内部调整 Skill 相对顺序的原因记录在 `design.md`，不构成需求变更。

## 影响范围

- 新增 OpenSpec 规格：`product-architecture`、`asset-library`、`reverse-prompt`、`prompt-library`。
- 解除归档变更 `bootstrap-vistash-development-workflow` 遗留的运行时技术栈待确定问题。
- 约束后续全部产品变更：任何引入网页抓取、把像素处理移入界面层、内置供应商密钥或加入静默降级的提案，都必须先修订本次规格。
- 不新增运行时依赖、不初始化应用代码、不修改公开 API：本变更只产出契约与决策记录。
- 仓库根目录的 Viko 调研蓝图从游离文档转为被规格引用的依据材料。
- 后续需要 `research` 补齐视觉模型供应商与生图模型的一手事实，其结论写回本变更或后继变更的 OpenSpec 产物。
