## ADDED Requirements

### Requirement: 两阶段视觉理解

反推 MUST（必须）分两次视觉模型调用完成：第一次只判定图像类型与粗结构，第二次使用该类型对应的观察 schema 执行细粒度观察。系统 MUST NOT（禁止）使用包含全部类型字段的单一巨型条件 schema，因为供应商通常只支持 JSON Schema 的子集，过深条件分支会提高拒绝率与语义错位风险。

#### Scenario: 反推一张动漫插画

- **WHEN** 使用者对一张动漫插画触发反推
- **THEN** 系统先判定图像类型为动漫插画，再使用动漫插画专用观察 schema 执行第二次调用

#### Scenario: 检查请求结构

- **WHEN** 检查任一次反推的模型请求
- **THEN** 不存在把所有图像类型字段合并进同一条件分支的单次请求

### Requirement: 图像类型枚举与 schema 路由

系统 MUST（必须）使用固定的图像类型枚举：`photographic_portrait`、`anime_illustration`、`poster_design`、`commercial_product`、`product_still`、`space_landscape`、`ui_infographic`、`mixed_other`。每次反推 MUST（必须）落到且只落到一个类型。

v1 MUST（必须）为 `photographic_portrait` 与 `anime_illustration` 提供专用观察 schema，其余类型 MUST（必须）落到一份通用观察 schema。新增专用 schema MUST（必须）在冒烟集上验证其相对通用 schema 的增益，未通过验证不得替换通用路径。

#### Scenario: 判定为尚无专用 schema 的类型

- **WHEN** 图像被判定为海报设计
- **THEN** 第二次调用使用通用观察 schema，且结果记录所使用的 schema 标识

#### Scenario: 新增一类专用 schema

- **WHEN** 为海报设计新增专用观察 schema
- **THEN** 在冒烟集上对比该类型使用通用 schema 与专用 schema 的结果，仅在专用 schema 表现更好时启用

### Requirement: 观察结果结构契约

观察结果 MUST（必须）包含 schema 版本标识、唯一图像类型及其置信度与依据、画幅与景别与视点、带可见证据与置信度的观察项列表、生成契约（必须保留项、可变项、需避免项）以及不确定项列表。

观察阶段 MUST NOT（禁止）输出颜色的 HEX 值，只描述冷暖、明暗、饱和度与区域关系。观察结果 MUST NOT（禁止）包含来源网页、平台、作者、水印或不可见的生成参数。对角色、作品与画师专名的判断 MUST（必须）具备多个独立可见锚点，证据不足时写入不确定项而非直接断言。

#### Scenario: 观察一张构图明确的图像

- **WHEN** 视觉模型完成第二次调用
- **THEN** 结果包含唯一画幅、互斥且一致的景别与视点，以及每条风格结论对应的可见证据

#### Scenario: 图像疑似特定角色但证据不足

- **WHEN** 图像特征只满足一个身份锚点
- **THEN** 该判断进入不确定项，正式观察项与提示词中不出现该专名

#### Scenario: 检查观察结果中的颜色描述

- **WHEN** 检查观察结果的颜色相关内容
- **THEN** 只出现冷暖、明暗、饱和与区域关系描述，不出现 HEX 值

### Requirement: 提示词编译与目标生图模型档案

提示词 MUST（必须）由独立的编译阶段依据观察结果生成，而不是由观察阶段直接产出最终文案。每个目标生图模型 MUST（必须）拥有独立且版本化的 `target_profile`，记录偏好的提示顺序、长度上限、负向约束的表达方式与画幅参数。

编译阶段 MUST（必须）严格保留生成契约中的必须保留项，MUST NOT（禁止）新增观察结果中没有证据的实体、专名、镜头参数或艺术家名。对外呈现与可复制的产物 MUST（必须）是自然语言提示词；结构化 JSON 只用于程序消费，MUST NOT（禁止）作为提示词直接展示给使用者。

档案的版本标识 MUST（必须）是带日期后缀的完整型号 ID，MUST NOT（禁止）退化为系列名，因为同系列不同日期的型号在长度上限与画幅参数上存在破坏性差异。

档案的四个原有字段 MUST NOT（禁止）建模为标量：长度上限 MUST（必须）同时记录数值、单位与是否硬上限；负向约束的表达方式 MUST（必须）是至少区分"有独立参数"、"须改写进正向提示词"与"无法表达"的枚举，并 MUST（必须）能记录参数生效的前置条件；画幅参数 MUST（必须）建模为形态类型加取值域，并 MUST（必须）能标注宽高书写顺序与边长取整规则；提示顺序 MUST（必须）标注其依据是供应商文档还是本项目自定义。

档案 MUST（必须）额外记录目标模型是否允许关闭服务端提示词自动改写，以及改写后实际生效的提示词是否可取回。在两者均为否的目标模型上，质量门槛的验收口径 MUST（必须）显式放宽并记录原因，因为此时无法归因失败来自本项目的编译还是服务端的改写。

提示词超出档案记录的长度上限时，编译阶段 MUST（必须）在请求发出前按显式错误码处理，MUST NOT（禁止）依赖服务端截断，因为静默截断会破坏本需求承诺的必须保留项。

编译阶段 MUST NOT（禁止）在没有 `target_profile` 的情况下产出提示词。若 v1 尚未正式选定目标生图模型，MUST（必须）使用一份显式记录的兜底档案，MUST NOT（禁止）以"暂无目标模型"为由跳过长度与负向约束的约束检查。

#### Scenario: 同一观察结果编译到不同目标模型

- **WHEN** 同一份观察结果分别按两个目标生图模型的 `target_profile` 编译
- **THEN** 产出两条按各自档案组织的提示词，且无需重新调用视觉模型

#### Scenario: 使用者修改一个观察维度

- **WHEN** 使用者修改观察结果中的某个维度后请求重新编译
- **THEN** 系统只重新执行编译阶段，不重新执行视觉理解

#### Scenario: 检查编译产物的证据一致性

- **WHEN** 检查编译出的提示词
- **THEN** 其中出现的实体、专名与镜头参数均可在观察结果中找到对应依据

#### Scenario: 编译产物超出目标模型长度上限

- **WHEN** 编译结果的长度超过档案记录的上限
- **THEN** 编译以显式错误码失败，不向目标模型发出请求，也不自行截断后当作成功

#### Scenario: 编译到无法表达负向约束的目标模型

- **WHEN** 目标模型档案记录负向约束为"无法表达"，而观察结果含需要排除的内容
- **THEN** 编译不生成该目标模型读不懂的否定句，排除项的处理方式由档案的表达方式字段决定

#### Scenario: 检查档案的版本标识粒度

- **WHEN** 检查任一 `target_profile` 的版本标识
- **THEN** 该标识是带日期后缀的完整型号 ID，而非系列名

#### Scenario: 目标模型无法关闭自动改写

- **WHEN** 目标模型档案记录自动改写不可关闭且改写后提示词不可取回
- **THEN** 该目标模型下的质量门槛验收口径附带显式的放宽说明与原因，而不是按可归因情形判定

### Requirement: 色卡由确定性算法独立产出

色卡 MUST（必须）由 Rust 侧的确定性像素算法产出，包含缩放采样、忽略低透明度像素、转换到 OKLab 色彩空间、确定性初始化的 K-means 聚类、小占比簇过滤、强调色补充发现、邻近簇合并、颜色角色标注与占比归一。

同一输入图像 MUST（必须）产出完全相同的色卡结果。输出的颜色值 MUST（必须）取自图像实际样本中的代表像素，MUST NOT（禁止）输出可能不存在于原图的聚类质心颜色。色卡结果 MUST（必须）携带显式状态字段；计算失败时 MUST NOT（禁止）返回空颜色列表冒充成功，且失败时颜色列表 MUST（必须）为空并携带显式错误码。

色卡结果 MUST（必须）携带算法版本标识。算法版本变更后，既有色卡 MUST（必须）重算；色卡作为派生数据 MAY（可以）被覆盖，不受提示词记录的仅追加约束。

每个颜色 MUST（必须）标注取自固定枚举的角色，且角色 MUST NOT（禁止）由占比排序推导，因为强调色的占比通常低于普通簇的过滤阈值，按占比排序会把它误判为次要色。

每个颜色 MUST（必须）同时记录可复制的十六进制值与其在聚类色彩空间中的坐标，后者供后续颜色筛选做距离计算，避免每次筛选重新转换色彩空间。

占比 MUST（必须）只在参与聚类的有效像素内归一并使总和为一，MUST NOT（禁止）被表述为该颜色在整张图上的面积占比，因为低透明度像素已按本需求被忽略。

结果 MUST（必须）记录降采样后实际参与聚类的像素数，作为同一输入产出同一结果这项承诺的回归判据。

颜色条目数 MUST NOT（禁止）超过八条。邻近簇合并后仍超过该上限 MUST（必须）按计算失败处理，因为这表示合并阈值过小，属算法参数问题而非图像特性，输出一串近似色会使色卡不可用。

#### Scenario: 同一图像重复计算色卡

- **WHEN** 对同一张图像重复执行色卡计算
- **THEN** 两次结果的颜色值、角色标注与占比完全一致

#### Scenario: 色卡计算失败

- **WHEN** 图像解码失败或有效像素不足导致色卡无法计算
- **THEN** 结果状态标记为失败并携带原因，颜色列表不被解释为"该图无颜色"

#### Scenario: 核对输出颜色是否存在于原图

- **WHEN** 检查色卡输出的任一颜色值
- **THEN** 该颜色取自原图实际采样像素

#### Scenario: 检查小面积强调色的角色标注

- **WHEN** 图像中存在面积很小但视觉关键的强调色
- **THEN** 该颜色被标注为强调色角色，而不是因占比低而被标注为次要色或被过滤掉

#### Scenario: 合并后颜色数量超过上限

- **WHEN** 邻近簇合并完成后颜色条目仍超过八条
- **THEN** 结果按计算失败处理并携带对应错误码，不输出超过上限的近似色列表

#### Scenario: 算法版本变更后读取既有色卡

- **WHEN** 色卡算法版本升级后打开一个此前已计算色卡的素材
- **THEN** 系统据其记录的算法版本标识判定需要重算，不直接使用旧版本结果

### Requirement: 反推任务状态机与幂等

即使界面只提供单张按需入口，反推 MUST（必须）建模为持久化任务，并且 MUST（必须）使用显式状态机：`created`、`validating`、`classifying`、`observing`、`compiling`、`completed`、`failed`。系统 MUST NOT（禁止）使用单一模糊状态覆盖多个阶段。

每个任务 MUST（必须）持有幂等键，并 MUST（必须）记录所用视觉模型标识与版本、各阶段耗时与失败原因。重复提交同一幂等键 MUST NOT（禁止）重复调用模型。

#### Scenario: 反推在观察阶段失败

- **WHEN** 第二次视觉模型调用失败
- **THEN** 任务状态变为 `failed`，并记录失败发生在 `observing` 阶段及其原因

#### Scenario: 重复提交同一任务

- **WHEN** 同一幂等键的反推请求被重复提交
- **THEN** 系统复用既有任务，不产生第二次模型调用

#### Scenario: 应用重启后检查任务

- **WHEN** 应用在任务进行中被关闭后重新打开
- **THEN** 该任务的状态与失败原因仍可从持久化记录中查得

### Requirement: 观察结果校验与至多一次定向重分析

观察结果 MUST（必须）在使用前通过确定性校验：必填字段完整、画幅唯一、景别与视点与渲染机制互斥一致、颜色描述未越界、提示词未引入无证据实体。校验失败 MUST（必须）返回明确错误码，MUST NOT（禁止）通过默认值填充或把原始文本整体当作提示词的方式静默兼容。

校验发现语义冲突时，系统 MAY（可以）执行至多一次有明确原因的定向重分析，并 MUST（必须）仅在冲突数量下降时采用重分析结果。系统 MUST NOT（禁止）无限重试。

#### Scenario: 观察结果缺少必填字段

- **WHEN** 校验发现观察结果缺少画幅字段
- **THEN** 返回对应错误码，不使用默认画幅继续编译

#### Scenario: 发现风格机制互斥冲突

- **WHEN** 校验发现硬边赛璐璐阴影与大范围柔和塑形同时出现
- **THEN** 系统执行至多一次定向重分析，且仅在冲突数量下降时采用新结果

#### Scenario: 重分析后冲突未减少

- **WHEN** 一次定向重分析后冲突数量没有下降
- **THEN** 任务以校验失败结束并保留两次结果供诊断，不继续重试

### Requirement: 反推质量门槛

v1 验收 MUST（必须）基于一个固定的 80 张冒烟集，覆盖八个图像类型各 10 张，并刻意包含复杂遮挡、低清、强透视、多主体与小文字等难例。每张图 MUST（必须）人工标注唯一画幅、图像类型、主体数量与关系、构图锚点、风格机制、光线关系、主色角色、材质、最可能跑偏项与不确定项。

验收 MUST（必须）与"直接让通用视觉模型生成提示词"这条基线对比，并 MUST（必须）达到：观察结果 schema 有效率不低于 99%、不存在静默解析兼容、在主体、构图与风格三个维度上相对基线有可见提升。评分 MUST（必须）分项报告，MUST NOT（禁止）只给出单一不可解释的加权总分。

规模更大的 300 至 500 张决策集延后到需要在两个方案或两个模型之间做选择时再建立。

#### Scenario: 提交一次影响观察 schema 的修改

- **WHEN** 观察 schema 或类型策略被修改
- **THEN** 在冒烟集上重新运行并分项报告主体、构图、风格、光色与稳定性结果

#### Scenario: 反推结果未超过基线

- **WHEN** 冒烟集对比显示结构化反推在主体、构图、风格三项上未超过直接生成基线
- **THEN** v1 该项验收不通过，并需回到类型策略与编译规则继续修订

#### Scenario: 检查评分报告形式

- **WHEN** 查看一次冒烟集评测报告
- **THEN** 报告分项列出各维度结果，而不是仅给出一个总分
