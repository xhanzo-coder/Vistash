## ADDED Requirements

### Requirement: 产品范围边界

Vistash MUST（必须）只覆盖两项能力：本地图片素材管理，以及基于图像可观察证据生成可编辑的生图控制提示词。项目 MUST NOT（禁止）包含从网页站点批量抓取素材的能力，因为该方向需要浏览器扩展或内置浏览器作为第二个产品面，并会引入按站点维护解析器的长期负担。

产品目标 MUST（必须）表述为"生成能在指定生图模型上重建主体、构图、风格机制、光色与材质的控制提示词"，MUST NOT（禁止）表述为"还原图像生成时使用的原始提示词"，因为从单张成图无法唯一恢复历史提示词字符串。

#### Scenario: 提出超出边界的变更

- **WHEN** 某个变更提案引入网页站点素材抓取、浏览器扩展或内置浏览器采集
- **THEN** 该提案必须先修订本需求，不得在现有边界下直接实施

#### Scenario: 编写面向使用者的功能描述

- **WHEN** 编写界面文案、文档或提交说明中描述反推能力
- **THEN** 描述使用"生成可重建相似视觉语言的提示词"，不出现"恢复原始提示词"或等价表述

### Requirement: 初始运行时技术栈

项目 MUST（必须）采用 Tauri 2、React 与 TypeScript、Rust 以及 SQLite 作为初始运行时技术栈。更换其中任一项 MUST（必须）通过新的 OpenSpec 变更完成，并记录被替换方案的失效原因。

本需求解除归档变更 `bootstrap-vistash-development-workflow` 遗留的运行时技术栈待确定问题。

#### Scenario: 初始化应用代码

- **WHEN** 首次创建应用工程结构
- **THEN** 工程使用 Tauri 2 承载桌面外壳、React 与 TypeScript 承载界面、Rust 承载后端逻辑、SQLite 承载索引

#### Scenario: 提出更换技术栈

- **WHEN** 有提案要求替换上述任一技术
- **THEN** 该提案通过独立 OpenSpec 变更修订本需求，并说明原技术为何不再适用

### Requirement: 媒体处理与界面渲染职责分离

图像解码、尺寸缩放、缩略图生成与色卡计算 MUST（必须）在 Rust 侧完成。界面层 MUST NOT（禁止）承担像素级图像处理，包括通过 `Canvas` 或 `OffscreenCanvas` 读取像素数据执行聚类或缩放。

#### Scenario: 实现缩略图生成

- **WHEN** 实现素材缩略图生成
- **THEN** 解码与缩放在 Rust 侧执行，界面层只接收已生成的缩略图数据

#### Scenario: 实现色卡计算

- **WHEN** 实现色卡提取
- **THEN** 像素采样、色彩空间转换与聚类在 Rust 侧执行，界面层只接收计算结果

### Requirement: 显式失败语义

所有文件系统写入、数据库写入、图像处理与模型调用 MUST（必须）具有明确的错误类型与错误码，并 MUST（必须）向使用者呈现失败原因。系统 MUST NOT（禁止）在失败时返回空值、默认值或部分结果冒充成功。

#### Scenario: 色卡计算失败

- **WHEN** 色卡计算因解码失败或像素不足而无法完成
- **THEN** 结果携带表示失败的显式状态与原因，不返回空颜色列表冒充成功

#### Scenario: 结构化输出解析失败

- **WHEN** 模型返回的内容不符合约定结构
- **THEN** 系统返回明确的校验错误，不把原始文本整体当作有效结果使用

### Requirement: 模型凭据所有权与可替换视觉理解层

应用 MUST NOT（禁止）内置任何模型供应商的 API 密钥或等价凭据。凭据 MUST（必须）由使用者提供并保存在本机。视觉理解能力 MUST（必须）实现为可替换的 provider 接口，使更换托管供应商或改用本机模型不需要修改观察结果契约与提示词编译逻辑。

#### Scenario: 首次使用反推能力

- **WHEN** 使用者在未配置任何凭据的情况下触发反推
- **THEN** 系统提示需要先提供凭据，并且不存在可用的内置默认凭据

#### Scenario: 更换视觉理解供应商

- **WHEN** 增加一个新的视觉理解供应商实现
- **THEN** 观察结果结构契约与提示词编译逻辑不需要修改
