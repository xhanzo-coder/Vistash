## Why

仓库已有 21 条生效需求与 19 条决策记录，却没有一行生产代码——没有 `package.json`，没有 `src-tauri`，应用无法运行。使用者已明确首要目标是先做出替代 Eagle 的 Windows 桌面框架，反推与生图在该框架之上再开发。因此现在需要一个贯穿全部架构层的最窄纵向切片：它让已定契约第一次在真实代码里受检验，也让此前只有文档的产出第一次变成可以打开、可以操作的东西。

## What Changes

- 初始化 Tauri 2 工程结构：Rust 后端、React/TypeScript 前端、SQLite 索引，并落地真实可执行的 lint、类型检查与测试命令。
- 新增应用外壳：首次运行选择库位置并创建库骨架（`library.json`、`folders.json`、`objects/`、`trash/`、`prompts/`、`index.sqlite`），再次启动直接打开上次的库。
- 实施导入管线：SHA-256 内容哈希、两级 fanout 寻址、同目录 JSON 侧车、库内与回收站两级去重、先本体后侧车的写入顺序、单素材回滚，以及九个 `import.*` 错误码。
- 实施 Rust 侧媒体管线：解码、降采样、缩略图生成，以及 OKLab 空间的确定性 K-means 色卡计算，含三个 `color_card.*` 错误码与至多八条颜色的自检上限。
- 新增缩略图网格浏览与单图预览，预览中展示色卡并支持复制 HEX。
- 实施 SQLite 索引及其从元数据文件的全量重建路径。
- 确定导航骨架并解除待确定问题六：提示词库在界面中的位置。
- 建立首批测试：色卡确定性、哈希与寻址、导入回滚不变量、索引重建等价性。
- **BREAKING** 无。仓库此前没有生产代码，本变更是第一份。

不在本次范围的部分及其理由：

- 文件夹、标签、按标签与文件名搜索三项属 v1 六件套，但它们是在地基之上的增删改查，并入本次会使一个尚未跑通的切片再扩大一倍。移到紧接的后继变更。
- 删除与回收站的界面同样移到该后继变更。但 `trash/` 目录与回收站去重检查必须在本次实现，因为 `import.duplicate_in_trash` 是已生效需求，导入管线绕不开它。
- 提示词库的功能实现延后。本次只在导航骨架里为它定位，避免日后加入时改动导航层级。
- 反推与生图不在本次范围，其字段级契约仍待后继变更补齐。

## Capabilities

### New Capabilities

- `app-shell`: 应用外壳的行为契约——库位置的选择与记忆、库骨架的创建与校验、导航结构、失败信息的呈现方式，以及"界面层不承担像素处理"这条既有约束在具体视图上的落地方式。

### Modified Capabilities

- `asset-library`: 新增缩略图契约需求。现有需求已把"缩略图网格浏览"列入 v1 范围，却未定义缩略图的尺寸、编码格式、存放位置与缺失时的重建方式。这些是实施前必须先定的行为约束，不属实现细节：缩略图是派生数据还是库内容，直接决定它是否参与索引重建。

## Impact

- 首次引入运行时依赖：Tauri 2、React、TypeScript、Vite，以及图像解码与缩放、SHA-256、SQLite 驱动、序列化等 Rust crate。
- 新增工程目录：前端源码目录与 `src-tauri/`。
- 触发 `setup-pre-commit`：真实的 lint、类型检查与测试命令在本次首次存在，此前无从配置。
- 库格式首次被真实写入磁盘。`library.json` 的 `format_version` 自本次起对外承诺，后续格式变更须走迁移路径而非直接改写。
- 解除 `2026-08-18-establish-vistash-product-architecture` 的待确定问题六。
- 不修改任何既有需求。本次实施的全部行为受 `asset-library`、`product-architecture` 的现有需求约束，其中"媒体处理归属 Rust 侧"与"显式失败语义"两条在本次首次被真实代码检验。
